# MinecraftAIBuilder B198Z-R80 — 使える公共図書館へ近づくための3D動線と支持の研究

基準：2026年10月22日 JST。既存 `feature/b198zr1-protected-architectural-revision`・Draft PR #128で継続。R79はWindows/UbuntuのCIが両方成功している。

## 重要な区別
R79ではOBJの原創形態は生成したが、利用者の入口から両翼・最上層ラウンジへのつながりは実装していなかった。R80はR79の3D三角形面を残しつつ、**右側4回の折り返し昇降、左側の書架翼用昇降、前庭での左右への分岐、連続デッキと踊り場、外殻への小型支持ブラケット、透明ラウンジ内の床**を研究用の同一3D座標系で追加する。

これは正規化座標の美術・動線コンセプトであり、物理単位、実Minecraftの安全性、階段/ランプの適合寸法、力学的な支持、衝突、実機歩行を証明しない。設計の空間的な連続と、本当に利用できる完成建築を混同しない。

## 具体的な3D改善
- 中央アトリウムを高所で橋や床が横切らない。海辺からの入口分岐は元の翼の南端よりも**外側の前庭部分**に配置し、中央空洞の主領域を保つ。
- 両翼の内側に人の動線を想定した幅付きデッキ（厚みあり）を作成。縦方向の上昇は側翼の長手方向を往復し、折り返し位置で水平な踊り場に接続する。
- 右翼の上端ではラウンジの楕円床へ平面上のデッキを接続する。既存のR79ガラスドームと接続するが、実際の頭上クリアランス・入口の開口・雨仕舞いは未検証。
- 支持材は外殻側からデッキに向かう斜材の表面モデルを追加。実際に荷重を伝える計算・アンカー・足場・衝突の検証は未実施。
- 前庭からの左翼・右翼分岐と上下の移動は一続きの概念経路として表現される。左右の書架・閲覧施設に分岐し、右翼は上層ラウンジへ到達するが、モデルが証明するのは**座標上の経路連続性と抽象傾斜だけ**。

## 自動的に検出する矛盾
`auditR80ResearchRoutes`：公共の4枝が全部あること、分岐の接続とラウンジ終点、連続した区間の退行や不自然な概念傾斜、中央アトリウムへの中心線の侵入を検出。真のMinecraftの歩行判定や面同士の完全な衝突検査ではない。

## 出力
`scripts/b198zr80-supported-route-concept-study.mjs`が R79の三角形OBJに、新規のスロープデッキ、踊り場、支持の側方ブラケット、ラウンジ床を追加し、研究用`R80_LIBRARY_RAMP_AND_SUPPORT_STUDY.obj`、同一複合メッシュから投影した正面・斜視・側面・俯瞰の4図、研究用の経路平面と縦断を収録した`R80_LIBRARY_ACCESS_AND_STRUCTURE_VIEWS.html`、出典・構成・未解決項目の`R80_3D_CIRCULATION_STUDY_EVIDENCE.json`を出力。

元モデル回答SHAとR79以前のR62→R76→R77→R78証拠を原本から再計算して照合し、R79の保存JSON改ざんやB143不合格の原本から過去の最終ボクセルが成立したという虚偽を拒否。R60一回オフラインZIPレビューから新規表示可能。

## 今後の美術・実用性検査
R80は、(1)単位付きの想定寸法と頭上空間、(2)連続した支持床と真の構造接合、(3)ラウンジ内の使える床・入口・ガラス外皮、(4)リアルな閲覧/書架配置、(5)正面・斜視・側面・俯瞰・室内からの人間の造形審査が次に必要と分かる研究段階。実寸化の前に建築的な一体感を人間が評価しなければならない。

`NOT_PREPARED`、施工9ゲートすべてBLOCKED、`constructionApproved=false`、`executionAllowed=false`、`BuildPlan.operations=[]`、モデル呼び出し0、Minecraft worldContacts/Reads/Writes=0。main、Freeze、既存R48・R54原本の変更なし。新たなQwen推論には別の単発明示承認が必要。
