# MinecraftAIBuilder 長期能力ロードマップ — 批判的再設計案（2026-10-31）
**種別：提案 / DRAFT、既存憲章・正式戦略を上書きしない。ユーザーとの合意で採用するまで方針変更ではない。**
ベース: [憲章](AI_PROJECT_CHARTER_JA.md)・[戦略v2](PROJECT_STRATEGY_V2_JA.md)・[自由建築現状](R125_FREE_BUILD_JA.md)・[3素材施工証拠](R125_THREE_MATERIAL_REAL_WORLD_PASS_20261031_JA.md)。
最終目標は「未知の自然言語から、美しく、内部と機能が使え、試験ワールドで安全に施工できる建築・プレイ可能なゲームマップを、AIが独創的に設計する汎用システム」。**Qwen3:14Bに依存して完成しない基本機能**も必須で、Mac 8GB級2Bから検証する。

## 現在地（証拠レベル別）
2026-10-24頃にはQwenの真のB143ボクセル化は成立例があったが、Minecraft試験施工未達。10/25〜30には3D/意味設計・階段・用途設備・品質監査を反復し、形式テストPASSでも美術不合格やMinecraft未施工が続いた。10/31にはQwenによる初見花屋933予定ブロックを石/ガラス主体で実機照合。独立した合成3素材建築502（stone348, oak_planks144, glass10）を実機で目視し `Positions and material counts match` 確認。その後のQwen建築924予定ブロックはユーザー画面で実施工外観を確認したが、予定セルの `mabverify` 成功と室内移動は未確認。
現行R125 ArchitecturePlanは原則1〜2階・16〜32幅・各階2機能空間・矩形中心。**「自由に依頼できる入力欄」≠「任意建築を自由に実現できる能力」**。多素材の一般合格・入口動線・美術は未認証。

## 変更できない憲章
- 設計判断の主役はモデル。用途名の置換・固定住宅の再利用・同一ファサード大量生産は一般化成功としない。
- 再利用する正規資産：B143のBOX/CYLINDER/ELLIPSOID/TORUS/BEAM/CSG/STAIR等、R125意味プラン、R190高自由度実験、幾何・動線監査、実機MakeCodeエクスポーター、保存原文のSHA、少数の既存レビュー/CI。
- 人間美術判断・実3D機能・実Minecraft歩行・実モデル未知用途・CIは別評価。失敗はHOLD。原モデル回答を修正してモデルの成果と偽ることは禁止。
- 個別ワールドを識別でき、バックアップと安全な範囲がある場合のみ、明示的な施工。世界への書込みとソース生成を分離。ユーザーの包括許可は有料API/PCのWork操作/mainマージ/破壊的改変に及ばない。
- Chat＋GitHub中心、Workは事前許可。元ローカル未コミット変更を壊さず、Draft PR #128とmainを保護。独立worktreeは必要最小限。ZIP/CI/工程番号を増やさない。
- Mac 8GB級小型モデルを基本建築の要件として早期に反映。27Bを基本条件にしない。

## 初案を批判した結果：不採用と修正
1. **不採用**「美術を最優先で無制限に先行」→ 実施工が再び止まる。**修正**：毎段階で新しい依頼→実3D→コピー試験世界へ繋がる縦貫デモを保持する。
2. **不採用**「同じモダン住宅を美しくする」→ 固定テンプレート/用途偽装/過学習。**修正**：未知3用途と保持評価課題を標準とし、同じ形・内装の使い回しをREJECT。
3. **不採用**「屋根と装飾だけ増やす」→ 元の箱構造の限界を超えない。**修正**：意図→空間グラフ→質量構成/断面→ファサード/照明→実3Dという層別IR。モデルが意図/主形状を選びエンジンが座標/支持/開口/施工を解く。
4. **不採用**「初手から自由なLLM生成コード実行」→ セキュリティと再現性崩壊。**修正**：データのみの可変形状・グラフ/制約ベース・既存B143 CSGを使用。任意コードは真の隔離環境の別研究ゲート。
5. **不採用**「マップは建築完成後に着手」→ 到達性/視線/対戦公平性/ゲームの物理条件を後付けして再開発。**修正**：中盤からGameplay IRとルート検査を並走、遊べる小型マップを先に作る。
6. **不採用**「大きな新テスト群を大量追加すれば品質向上」→ 2026-10月の監査増殖を再発。**修正**：各能力につき小さな正例・負例と実機1件、変わったコードに関係するCIだけ。
7. **不採用**「大きいQwenだけ完成して最後にMac移植」→ 大型モデル特有の長い出力仕様に依存。**修正**：小型モデル用の短いIR・トークン予算・低RAMをM1から評価。
8. **不採用**「華やかな生成画像を品質の証拠に」→ Minecraft 3Dと乖離。**修正**：実ソース同一の3Dビュー/ゲーム画面を5〜7固定視点で人が比較。
9. **不採用**「10月最後の1週間を全工程に線形外挿」→ 施工橋接続の速さと美術/一般化の難易度は異なる。**修正**：1週間を最短縦貫の基準にのみ使い、以下の期間は仮説とする。

## 修正版アーキテクチャ
自然文・優先制約 → 小型でも扱える短い設計意図 → ProgramGraph（機能・部屋・隣接・移動） → MassingGraph（主/従ボリューム・高さ・ずれ・空洞・断面） → EnvelopeStyle（窓/庇/屋根/素材/室内役割） → 共通B143/CSG実3D → 独立した頭上高/支持/入口/経路/材料/敷地/安全監査 → Education adapter（事前検査・chunk化・進捗・中断/差分・復帰） → 実世界内検証。
ゲームマップは同じ空間・形状・施工エンジンを使用しつつ、Architecture IRとは別の GameMode IR（勝利条件・スポーン・資源・ルート・視線・対称性/非対称性・ジャンプ/射線・遊戯時間）を持つ。モード名による丸ごと固定レイアウトを避ける。
モダン建築は品質テストの代表例であり、モデルの全設計を「白い箱」に固定しない。モデル/美術QA/施工の責務を混ぜない。

## モデル採用判断
- **最初はQwen3:14Bを継続**：形状IRを変えるたびにモデルを変更しない。現行システムの限界とモデル限界の混同を防ぐ。
- 同じ未知依頼・同じIR・同じ施工器で、保存済みQwen/Gemma/小型モデルの1回応答、要求充足・構造・美術・速度・使用メモリを並べる。失敗時の明示的なモデル切替は可、出所を区別。
- モデルの学習・LoRA・大規模微調整は、IR+コンパイラ+安全な修復で改善しない欠陥が実測で残った場合のみ検討。過去原文を修正して「モデルが成功した」としない。

## 開発ペースの再較正と運用
10/24〜10/31の約7日で「世界施工なし→Qwen花屋実施工・3素材合成施工→追加の初見LLM平屋外観」という速い縦貫前進。ただし実時間/週あたり稼働と未知用途10件の成功率は未計測、精確な所要時間の推定はできない。上表は**非保証の条件付き工数予測**。
- **集中運用（週15〜25h相当）**：上表の暦期間を初期仮説とする。
- **週5〜8h相当**：多くの工程はおおよそ2〜3倍以上長期化し得る。モデル/既存ソースの再利用で短縮もあり得るが保証なし。
- **20h超/週でも**：美術・試験世界・ユーザー審査の待ち時間は比例短縮しない。
- 毎週1回、成果/障害/次の1つのゲート/実工数/手動操作回数を記録し、4週ごとに期間予測を更新。実際の品質進捗が0なら小改善の連発を止めてIR/評価軸から見直す。
- 1工程は意味のある実装/差分＋必要CI＋実3D比較＋必要なら1実機試験をまとめる。アイデア調査だけ、監査増殖、R番号の量産を完成扱いにしない。新たな建築固有修正は最大2回、その後は一般原因を直す。
- G0→G1の最初に**固定の検証セット：住宅・店舗・研究施設・図書館・住宅以外の用途の保持課題**を設定。うち一部は非公開の初見テスト（ユーザーの判断で追加）で評価し、モデル/エンジンをそこへ過適合させない。
- 自動視覚AIは補助。最終美術PASSはユーザー判断、実Minecraft映像を必ず含む。画像生成による完成図で代用しない。
- 新たなエンジン導入は、既存B143では達成できない最低3件の具体失敗が出た場合だけ。CIや3D出力ファイルの数で進捗を測らない。

## 最優先の次の大きな実装束（G0〜G1）
1. 今の自由入力経路の**未完了CI/安全な材料パレット/完了までの進捗通知**をまとめて検証。現状の「自由入力＝自由建築」という期待過剰をUIで防ぐ。
2. 題材を変えたQwen本物3件で原文/IR/外観を比較し、**モデルが決定した主形状・用途**と共通エンジンが強制した寸法/屋根/間取りを可視化。サンプル住宅を華美に仕上げるのではなく本当の多様性を測る。
3. 単独入室/屋内動線・床支持・頭上空気の最終ボクセル検査、用途汎用設備の配置（ふさぐ場所は拒否）。2階の階段実機を確認する。
4. 検証済み材料を1種類ずつ拡張。未認証を黙って石に変えない。MakeCode安全な事前検査のchunk/進捗/タイムアウト、実行計測。元世界は触らない。
5. 1回で3用途実機試験が完走したらG1へ。未達ならHOLDし、なぜ通らないかを共通原因へ戻す。
