# MinecraftAIBuilder — 品質最優先・短期実証と長期一般化の統合計画（第3次精査）
**2026-10-31 JST / 位置付け：正式戦略への修正提案（DRAFT）。** 既存の[固定憲章](AI_PROJECT_CHARTER_JA.md)、[戦略v2](PROJECT_STRATEGY_V2_JA.md)、Draft PR #128の安全境界を変更しない。新計画の狙いは、過剰な直列ロードマップと、成果にならない検証・書類・ZIP増殖を解消すること。

## 0. 結論
「初めて納得できるモダン建築1棟」まで42〜75週は過大。最初の実証、未知依頼での再現性、広い用途での長期安定運用を分ける。既存のB143は box/cylinder/ellipsoid/torus/beam/stair/ADD/CUT を備え、R190にも空間質量の研究資産がある。大きな困難は機能をゼロから作ることではなく、**モデル由来の主形状・内部用途・開口/動線をひとつの実3Dに矛盾なく落とし込み、審美的な出来を繰り返し保証すること**にある。

### 証拠に基づく現在地
- Minecraft Educationで初見Qwen花屋933予定セルの実施工を確認（石/ガラス主体、室内通行未確認）。原本は凍結。
- 合成B143の502セル・石348/oak_planks144/ガラス10が `Positions and material counts match` をゲーム内で表示、外観もユーザー目視PASS。これは実LLMの未知用途一般化には算入しない。
- 2026-10-31、Qwen由来924セルの別棟が実ワールドの外観写真で施工済み。ただし全セルのmabverifyと入口/用途・室内機能は未検証。外観はユーザー判定で低品質。
- 現行R125はおおむね1〜2階、16〜32ブロック平面、各階2空間の矩形中心の意味プラン。B143基盤自体はもっと自由な形状を表現可能。R190の一部研究はART REJECTであり、新IRへ接続しただけで採用できない。
- ユーザーは日曜約8h、残り6日平均約2h＝**週約20h**の作業機会に加え、通学・外出・学校の短い休憩からスマホでGitHub中心の実装指示が可能。さらに外出中でも、**リモート機能を使い、限られたPCローカルの操作・モデル実行・場合によっては限定したWork作業が可能**との申告。ただし実際の接続・遠隔操作可否、操作範囲、待ち時間は未計測。PCへのWork/Computer Useは従来どおり個別許可が必要である。

## 1. 最終目標（変更なし）
未知の自然言語から建築・ゲームマップの用途、機能関係、独創的主形状、内部空間、材料、家具・設備、入口・階段・経路、景観・地形・ルールをLLMが考え、再利用できる非LLMエンジンが安全で再現可能な真正3D・Minecraft Education施工データにする。施工前の安全性、実機内の歩行可能性、遊べるゲーム性、人の美術評価を独立して証明。Java/大規模都市/高度なPC連携は後の拡張。小型Mac 8GB級2Bから基本建築を構成できる短い設計IRの方針は維持し、27B依存にしない。

**成功を3階層に分ける：**
A. **作品レベル**：初見のモデル応答から一つの魅力的な実3D/実Minecraft作品が実現できる。
B. **能力レベル**：異なる初見用途3〜10件でも、モデル自身の判断が形状・内部に反映される。
C. **製品レベル**：連続した依頼、失敗回復、ワールド安全、ユーザー操作数、軽量モデルまで安定して運用できる。
AのためにCを完成させてはならない。AをもってCの達成宣言をしてもならない。

## 2. 機構の最短設計
**自然文 → Mini Design Intent（小型LLM対応） → ProgramGraph（用途・関係・出入口・室内経路）＋MassingGraph（作者が指定した質量・奥行き・高さ・ずれ・切除・空洞） → B143既存CSGによる実ボクセル化 → 外装/内装の役割・確定パレット → 3D機能QA・要求充足QA・人の美術審査 → Educationの安全なチャンク/差分施工 → 実機で歩行/素材/機能確認**。
最初は「直方体2〜4個をずらす・つなぐ」「大きな庇/テラス」「明確な主入口・大きな採光」「内装役割」を自由に組み合わせる。この数はホスト固定テンプレートではなく、**モデルの主形状選択の最初の小さな表現領域**。制約が作品の発想を切っている場合は段階的に拡張。
GameModeGraph（スポーン/対戦条件/資源/移動・ジャンプ・視線）は建築表現とは別のIRとし、同じ3Dボクセル/ワールド施工エンジンを共有。BedWarsの固定マップを複写して「汎用マップ生成」と呼ばない。

## 現時点で本当に複雑な部分はどこか
- **比較的簡単**：追加の箱/庇/採光/屋根形状をB143で作り、Qwenの短い新しい意図に結びつけ、1棟をMakeCodeへ出す。最初の魅力ある作品まで半年を要する必然性はない。
- **中程度〜難しい**：建築主形状・各用途室・ドア・階段・空洞・外殻を矛盾なく統合し、未知用途でもモデルの独創性を失わない共通設計器にする。最初の成功と10件中7件の成功を混同しない。
- **難しい**：美術4/5以上を未知依頼で安定して達成すること、内部と遊びが成立するゲームマップ、別モードの公平な資源/経路設計、Mac8GB実機の速度/メモリ、都市規模の安全な復元と分割施工。
- **実装上の明確な制約**：現行Education exporterは単回の予定配置20,000ボクセル上限、設計対象の直方体外接領域40,000セル上限、compactCuboidsの通常2,500件上限、ソース180,000バイト上限。これはB143本体の形状表現力とは別の**ワールド出口のパイロット制限**。大規模マップ・街区に進む際は分割・進捗・重複安全性・復元の実装が不可欠。小住宅で全制約を解く必要はない。

## 3. 初案を批判した修正（採用）
1. **旧G0〜G6を直列で42〜75週** → 早い作品まで必要以上に遅く見える。初回作品A、再現B、安定Cを分離し、互いの実装を適切に並行する。
2. **美術は後から** → 違う。初回からユーザー自身の5段階評価を使い、モダン作品が低品質ならコードや部材数が増えてもREJECT。見た目は後付け装飾で取り繕わず主形状を直す。
3. **一棟だけ徹底改修** → 固定テンプレートに過剰適合する。毎回、美術を狙う1件と、設計が異なる用途2件を並走。2回同一作品を直しても不合格なら一般のIR/形状コンパイラへ戻す。
4. **3Dエンジンを新規開発** → B143とR190の既存研究をまず再利用。限界を示す具体反例が3件そろわない限り全面再実装しない。
5. **入力が自由＝生成が自由** → 現行R125に矩形/階数/材料制約が残る。制約・モデル判断・コンパイラ補助の出所を出力で表示。未対応を暗黙の家テンプレートに置換しない。
6. **大量CIで品質を証明** → 検証は軽量の正/負回帰＋真正3D＋人間のゲーム画面評価。Aソース/B幾何/C美術/D実世界/Eモデルの5軸を分離。
7. **ゲームは建築の完全完成後** → ゲームの実経路/ルール/対戦公平性は早い段階に小規模検証。まず遊べる一マップを成功させる。
8. **巨大LLMが必要** → 実測で不足とわかるまでQwen3:14B基準。Gemma/大型は比較、基本モードの2B/4B低資源検証を初期から続ける。
9. **遠隔操作は無条件に自動化できる** → できるのはユーザーが接続できる時/許可された範囲のみ。認証、誤操作、ワールド識別、オープンなWorkの利用枠に依存しない安全な設計。
10. **毎週20hが全部コード作成に使える** → ローカル実機審査とスマホ指示の実工数を区別。外出時操作の追加で開発者の実稼働時間を二重計上しない。

## 5. 実作業の3レーン＋安全境界
**レーンA — スマホ/GitHub**：通学・休み時間・外出中の各ターンで既存HEADを確認、設計→実装→絞ったテスト→コミット→CI追跡を一括。原則、コードのみで完結する工程を毎ターン進める。ソースの正本はDraft PR #128。質問の連発や1ファイルずつ分割した工程報告は避ける。チャット未起動中にAIが勝手に長時間作業を続けるとは約束しない。

**レーンB — リモートPC（接続できる時だけ）**：ローカルQwen/Gemmaで未知依頼の本物の回答取得、真の3Dビュー/サムネイル生成、テストの実行、必要な実行ログ/SHAのGitHub記録。リモート操作は短い確認単位で利用し、既存ワールドや未コミットファイルを勝手に触らない。リモート機能とChatGPT Workは同一物ではない。Work/Computer UseでユーザーPCを操作する場合は、**その操作範囲の明示許可**を必要とする。外出先でゲームの操作が可能な時も、ワールド識別/バックアップ/安全条件を満たすまでは施工しない。

**レーンC — 自宅PC（日曜約8h＋平日平均2h）**：実Minecraft Educationでの美術/室内動線/実プレイ、複数用途の品質比較、リモートでは難しい操作のまとめ打ち。日曜は目安：ゲーム内検査3〜4h、3D美術評価2〜3h、ローカルモデル比較と翌週の課題整理1〜2h。予定に縛らず、失敗したゲートの実測と美術改善を優先。

**工程管理の固定ルール**：各スマホ作業で「完成させる意味ある能力・証拠・未実施の実機部分・次のPCコマンド」をGitHubに短く残す。PC実行はできる限りまとめる。ユーザーの未コミットr190aa/r190abや出力物に対し、無断stash/reset/force-push/上書き禁止。凍結モデル原文、Qwen花屋933、502成功建築、main、PR Draftを保護。安全に存在確認できないGitHub/PC操作はHOLD。

## 6. 2週間で真偽を判定する具体的な短期実験
- **最優先の実験E1**：同じQwen3:14Bで、モデルが主形状を選んだ実3Dモダン建築1件＋用途が異なる2件を、**独立原文・同一IR・同一施工器**で生成。外見が全部「平屋箱」に収束したらREJECTしてMassingGraphを変える。装飾のみを後付けしない。
- **E2**：モデルの選択/コンパイラの必須構造を独立表示。ユーザーが優先する空間/用途を捨てた偽の「モダン」を不採用。建物内部の支持床、3ブロック頭上空気、入口→主室到達をチェック。
- **E3**：ひとつをバックアップ済み別試験ワールドに施工、ブロック照合＋入口/室内の実歩行＋5視点写真でユーザーが美術判定。3素材以外は1種ずつ実機確認で許可リストを増やす。
- **E4**：必要な最小限の施工高速化。現行の安全事前検査を無根拠に省略せず、進捗/中断とチャンク処理の実測値を比較。ワールドが違う可能性・重複施工時はHOLD。
- **E5（並行）**：BedWars系のモード構造・独立オリジナル地形/道/島/スポーンを要求IRとして小さく試作。最初から完全サーバー実装・装飾全完成を求めない。

**2週後の再判定**：実モデルの成功数、相違する主形状数、ユーザー美術点数、通行/実機の失敗、スマホからのターン当たりの意味あるGitHub改修数、遠隔PC接続成功/失敗、Minecraft操作回数、CI/ワールドの待ち時間。短縮が成立していなければ計画期間を延長し、原因を確認する。最初の1作品で人間の評価が4/5を超えても、初見10件の成功率を推定しない。

## 7. 判断の前提・不確実性
前回の42〜75週は「安定した多用途・多モード・大規模運用」レベルには参考になっても、1棟の高品質実証までの期間として過大だった。新しい1〜3週／6〜12週はチャット＋GitHub＋接続可能なリモートPCを頻繁に回せる場合の挑戦目標であり、統計的な達成確率は**わからない**。実3Dの品質、未知用途への多様性、低RAM実機の挙動、リモートPCの安定性に未測定事項がある。最短期間だけを守るために品質、モデル著作性、安全を犠牲にしない。

**最上位に戻る基準**：見た目が3回続けてユーザーART REJECTになった／モデルの3件が同じ箱に潰れた／ユーザーの要求が素材置換や用途削除で失われた、のいずれかが発生したら小部品追加を中止し、IR/マス構成・作者判断の保持・美術審査方法を再設計する。これまでのモデル原文を改変して成功と記録しない。
