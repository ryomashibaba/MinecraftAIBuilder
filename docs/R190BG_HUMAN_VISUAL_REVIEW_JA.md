# R190-BG — 真正B143の人間批評を簡単に記録するオフライン審査画面

2026年10月29日 JST。既存Draft PR #128／feature/b198zr1-protected-architectural-revision／SOURCE ONLY／ART HOLD。

## 何が足りなかったのか
R190-BFのモデル生成条件の固定はUbuntu・Windowsとも成功したが、建築の美術品質は未立証。R190-BEには保存原文からの3D、五投影、断面、未採点JSONがある。しかし利用者が実際の3Dを見て評価し、どの視点の何を根拠に点数を付けたかを保存するには手編集が必要だった。さらに、不正な構造を含む建物こそ失敗例として目視批評する必要がある。

## 今回実装したこと
`scripts/r190bg-source-anchored-review.mjs` は、保存済みR190-BEの比較フォルダーだけを読む。実モデルを呼ぶ処理、MinecraftワールドAPI、形状の修復・生成処理は含まない。

1. `R190BE_COMPARE.json`と`R190BE_HUMAN_REVIEW_TEMPLATE.json`の元依頼SHA、原文SHA、B143形状SHA、技術判定・安全境界を照合する。有効なB143の3Dがない案を合成形状で置換しない。
2. 既存のA/B真正B143回転3D・正面/背面/東/西/屋根投影・断面を**そのままのバイト列で**新規フォルダーに複製する。再レンダリングや別の造形補修を行わない。全ファイルSHAを`R190BG_REVIEW_MANIFEST.json`に記録する。
3. `R190BG_REVIEW.html`に2案を並べて表示し、既存R190-BEと同じ4項目（用途適合／内部体験／質量と空洞・支持／独創性）を0〜4で採点、根拠にした具体的な投影・3D・断面と8文字以上の観察を選択・記入できる。未評価も選べる。
4. 画面のボタンで`R190BG_HUMAN_OBSERVATIONS.json`をローカル保存できる。署名のない人間の観察と明記し、ART PASSは一切自動発行しない。
5. `validateR190BGObservations`は、回答の対象比較SHA・審査画面マニフェストSHA・評価項目・点数範囲・根拠の視点・元の画像/HTML SHAを照合する。観察済みでも正式美術採用は0のまま。

## 反省に基づく修正
元案では、R4の機能HOLDの形状を表示対象から除外していた。しかし実モデルの失敗を批評することが学習に重要である。R190-BGは、**有効なB143原形状がある限り**R4や同一高さの動線がHOLDでも技術判定を明示して表示し、欠陥を人間が指摘できる。ただし機能HOLDを通行可能・安全と認定することは絶対にない。
また、審査項目の文言はBEが保存した原本と完全一致させている。作成時の基準を後から黙って変更しない。

## 人の操作
R190-BFで両側の保存済み原文が存在し、BE比較が作られた場合は、以下の**オフラインの一操作**だけで審査画面が生成できる。

```powershell
node scripts/r190bg-source-anchored-review.mjs --compare "R190BE_COMPARE_FOLDER" --out "NEW_REVIEW_FOLDER"
```

あとは`NEW_REVIEW_FOLDER/R190BG_REVIEW.html`をブラウザで開き、3D・投影・断面を確認し、直接フォームに入力してJSONを保存する。追加アカウント、外注、ZIP展開、モデル再実行、Minecraftのワールド起動は不要。保存されたJSONは次チャットで評価検証に用いることができる。

## 品質保証の限界と安全性
コードが判定するのは**保存済み元形状との一致と、観察コメントの書式・証拠の整合性**まで。レビューアーが本当に人間か、見たものが創造的で美しいか、評価が公平か、モデルdigestが同じか、階段を実歩行できるかは自動認定しない。正確なブラインド比較でもない（保存ソースの文字から方式が推測されうる）。
GitHub CIにはハードコードした合成B143と偽Ollama応答だけを使う。そこで得られるPASSは画面・証拠と安全動作の技術検証であって、建築の美的完成を意味しない。実モデルの品質比較には独立な人間観察と実原文が必要。
