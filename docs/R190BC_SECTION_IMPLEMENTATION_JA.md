# R190-BC 第2チェックポイント — 設計先行の入口と原文SOURCE断面監査

## 判定と出所（2026-10-29 JST）

本工程で実装したのは次の3点です。

1. 既存の **direct B143 + R4** 形式（\`design\` / \`explanation\` / \`assumptions\` / \`spatialPlan\`）を変更せず、用途→体験→空間断面→質量/空洞/支持→実ボクセルの順序をモデルに要求する **設計先行プロンプトの生成関数**。
2. モデルの**保存済み原文**を改変せず、B143の加算/切削後のSOURCE形状から、モデルが宣言した各機能領域の床支持・2幅立脚・頭上空気・上部占有物を実測する**断面監査器**。
3. モデルを呼ばずに、元の日本語依頼からプロンプトを生成したり、保存済みモデル原文をSHA256で照合してSOURCE断面を調査する**オフラインCLI**と、Ubuntu/WindowsのCI。

- \`.github/workflows/r190bc-original-section.yml\` — 2 OS検査、保存済み実R190-AAのHOLD証拠（実モデル再推論なし）。

## 設計上の重要な非変更点

- 新しい建築ジャンル、カテゴリ別テンプレート、幾何プリミティブ、ホストによる自動補修は追加しない。
- 既存の \`runR190Local\` / R190-R / R190-S / R190-AA のモデル呼び出し方針と既存保存プロンプトを**変更しない**。過去の試験のSHAが変わり、勝手に再推論されることを防ぐ。
- 新しいR190-BCプロンプトは**オプトインの準備経路**であり、既存のモデル実行経路にはまだ接続していない。モデル推論、新設計、品質の向上は実証していない。
- SOURCE断面に表示する青いセルは**実B143最終ボクセル**。塗り足し、未CUT部分の修理、モデル説明による幾何の上書きはしない。
- 保護対象原文のUTF-8バイト列とSHA256を維持し、新しい出力ディレクトリしか作らない。

## なぜこの断面監査が必要か

R190-Tは支持された立脚点や到達可能性のSOURCE proxyを観測できる。一方、モデルが記述した「用途領域」の中に、**幅2×2で支えられ、指定の頭上高さを満たす床領域が本当にあるか**、そして上部が覆われる範囲と天空側の範囲がどう分布するかを、断面に結びつけて確認する独立の局所的な証拠が必要だった。

今回の監査器はモデルが申告した \`functionalZones\` の座標範囲だけを対象とし、各高さで最終SOURCEの2×2立脚パッドを数える。全パッドの4列に上方固体がある場合は **roofedPad** という代理表示、全4列にない場合は **skyOpenPad**、中間は **partlyRoofedPad** に分類する。これは**天候保護、採光性能、実部屋の成立、支持強度ではない**。形の名称やモデルの自己申告ではなく、SOURCEに存在するセルだけを用いる。

\`SOURCE_SECTION.svg\` はモデルの入口 \`z\` 高さではなく、**入口のz座標に固定したx-y切断面**。領域がその断面に無ければ映らない。断面1枚が建物全体の代表性を保証しない。五方向投影・内部視点・美術審査は別途必要。

## 起動（研究用、モデル起動なし）

Windowsの既存正規リポジトリからNode.jsで実行する方式。CLIは新しい出力先を要求するため、既存の原文・レシートを上書きしない。

原依頼の別ファイルがある場合（先にSHA256を調べておく）：

\`\`\`powershell
node scripts/r190bc-offline-review.mjs --brief "C:\path\original-brief.txt" --sha "<実際の64桁SHA256>" --out "C:\path\new-prompt-study"
\`\`\`

保存済みの **direct B143 + R4** 回答を厳格に読む場合：

\`\`\`powershell
node scripts/r190bc-offline-review.mjs --original "C:\path\model-response.txt" --sha "<実際の64桁SHA256>" --out "C:\path\new-source-review"
\`\`\`

生成された \`DESIGN_FIRST_PROMPT.txt\` を既存モデルへ実際に送る処理はこのCLIに存在しない。意図しない推論や使用量消費は起きない。提出されたモデル原文が無効なら \`HOLD_INVALID_ORIGINAL_R4_OR_B143\` と記録し、架空のSOURCE投影を作らない。
