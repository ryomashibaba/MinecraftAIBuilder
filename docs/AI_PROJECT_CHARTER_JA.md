# MinecraftAIBuilder — AI継続開発憲章（固定方針）

**ここは長期間維持する原則。実行の最優先方針は [MinecraftAIBuilder戦略 v2](PROJECT_STRATEGY_V2_JA.md)、具体的な次の作業は [R125最短MVP](R125_THIN_VERTICAL_SLICE_PLAN_JA.md)、現在地は [AI_RESTART_JA.md](AI_RESTART_JA.md) を参照する。**
B100時代の `docs/B100_START_HERE_FIRST.md` は歴史的資料であり、現在のR96時点の作業入口ではない。

## 目的・成功条件
- 自然言語で未知の建築用途・世界観・機能・立地・規模を受け取り、AI自身が独創的な外観・内部・空洞・階層・床・入口・昇降・家具・動線を同時に設計する汎用AI建築システムを実現する。
- 現物の実3D形状から美術・機能・幾何を別々に審査し、改善する。**2026-10-24のユーザー包括許可により、Qwen/Gemma実推論とMinecraft Educationの試験施工は都度の再承認なしに実行できる**。ただし実行先特定・安全な施工計画・検証・バックアップ・停止条件など技術的安全ゲートを通過した場合のみ実行する。Java対応は後段。
- **最優先は建築としての独創性と美術品質、外形・内部・用途の一体性、使える空間**。JSON整形、形式的PASS、テスト本数、R番号増加は成功条件ではない。
- 現在の《潮光の裂帆図書館》はc01ベンチマーク用の **AIではなく人手/コード作成の独立3D美術研究**。汎用テンプレート化しない。他用途の生成能力やQwen改善の証拠にしない。
- 建築に使う形状、塔、リング、アーチ、曲面、浮遊床、材質などは先入観で禁止しない。箱の装飾だけ・閉塞した空洞・偽物の階段や経路では不合格。
- 正面/斜視/側面/俯瞰/内部/入口/主要室/上下動線を必要に応じて確認。美術は人の審査が必要で、ソースからの2D投影や数値PASSに置き換えない。
- **検証の区別：** (A) ソース/CIの整合、(B) 実メッシュ上の幾何・機能候補、(C) 人による美術品質、(D) 実Minecraft環境での可用性、(E) 実モデルの汎用生成能力。Aが成功してもB〜Eは自動昇格しない。

## 許可と技術的安全境界（2026-10-24 方針更新）
- **ユーザーがQwen/Gemmaの実推論とMinecraft施工を包括的・回数上限なしで明示許可した。** 今後はこれらを毎回再承認させない。Qwen/Gemmaのローカルモデル切替、反復試験、試験ワールドへの実建築とその読み取り・検査もこの許可に含む。旧「実推論0/World0維持・個別許可必須」方針は本項で撤回する。
- **包括許可は、すべての検査ゲートを無条件でPASSにする意味ではない。** 運用コード上の初期状態 `readiness=NOT_PREPARED`, `constructionApproved=false`, `executionAllowed=false`, 9×BLOCKED, `BuildPlan.operations=[]` はフェイルクローズ初期値として維持。対象ワールドと施工範囲、事前バックアップ/復元手段、命令数・実行中断、座標/周辺保護、幾何・構造・動線の最低条件を確認した特定の施工だけ安全にゲートを進める。**ユーザーの包括承認は満たされているが、技術的準備完了は別問題**である。
- デフォルトは専用の試験ワールド。作業対象やワールドを誤認できる状態では書込禁止。旧Freeze・B143/Qwen原本・保存済み世界を破壊せず、既存建築の破壊を伴う処理は隔離・可逆化する。施工前後の差分と実3D成果を記録し、失敗はHOLDのまま。
- 有料API/課金、ユーザーPCのローカルWork/Computer Use、第三者環境へのアクセス、mainマージ・PR #128のReady/Close/Mergeなどはこの包括許可の対象外で、従来の個別の制限を維持する。
- mainマージ、PR #128のReady/Close/Merge、旧Freeze、B99/B100、凍結されたB143/Qwen原本の改変、強制push・履歴破壊は禁止。安全な研究ブランチへのコードコミット・通常pushは継続可。
- 保存済み実Qwen図書館原本のSHA256：`40810c69e56e59f61704ef0e0a1d96f98a2415aa057a86d7355c44421ab3edbf`。原本はB143 HOLD、構造・動線不成立。後年のアシスタント生成形状と出所を混同しない。
- 失敗・未審査はHOLD/NOT_REVIEWEDのまま保存する。原本の上書き・合格偽装・実行したふりは禁止。

## 再設計の固定原則（2026-10-24）
- 実際に使える建築を作る最短縦貫動線が優先。B143コンパイラとB198G/H実ローカルLLM連携を再利用し、自然言語→モデル→真正3D→最低限QA→試験施工を先につなぐ。LLMが元から持つ発想・設計能力を、多数の特定建物プログラムで置き換えない。
- Macの小型LLMでも基本建築を可能にするため、モデルは短い意味設計、共通エンジンは正確な座標/材料/階段/施工へ分担する。最初から過度に厳しい固定部材JSONを要求しない。任意コード生成は安全な隔離環境を確認するまで禁止。
- 《潮光の裂帆図書館》は回帰資料に留め、主工程から外す。他の一つの建物へ移って固執することも禁止。2連続の建物固有の修正後は共通原因へ戻す。
- 旧R125〜R304の工程数前提ロードマップは取り下げ。MVP、3用途実証、Mac小型モデル実証、美術/実用性強化という**能力の通過条件**で進める。GitHub CIの成功を建築や実モデルの成功と混同しない。

## 品質・効率
- Chatと接続済みGitHubを基本とし、Workはユーザー承認があり明確に優位な場合だけ。Plusの利用量とユーザーの手作業を節約。
- 既存の継続ブランチとOpen/Draft PR #128を使い、小〜中規模で意味のある差分とコミットを積む。ZIP/CMD/ワークフロー/再認証を工程ごとに増殖させず既存R60レビュー経路を再利用。
- PR/pushの軽量テストとworkflow_dispatchの完全回帰を区別。省略・キャンセル・失敗を隠さない。
- 現実の不具合を優先し、検査だけの開発に戻らない。実Qwen/Gemma推論と試験ワールド施工を積極利用し、バックアップ・差分・3D証拠・復帰手順を残す。
- **引き継ぎは毎日書き直さない。** 工程が実質的に進んだコミット時のみ [AI_RESTART_JA.md](AI_RESTART_JA.md) の「確認済み現在地/次工程/重要ブロッカー」を最小更新する。長い履歴は既存R番号別docsとGit履歴で保存。記載されていない新事実はGitHubで検証する。

## 軽量MacローカルLLMでも基本建築を生成する（追加最上位目標）
- **Apple SiliconのMacノート、統合メモリ8GB程度を最低目標とし、16GBでは余裕を持たせる。** 8GB環境では2B級の4-bit量子化モデルから検証し、16GB環境では4B級も検証。具体的な動作速度・常駐メモリ・発熱・成功率は実機測定するまで未確定。
- 候補：Qwen3.5-2B / 4B、Gemma 4 E2B / E4B（対応ランタイム・量子化を事前確認）。大規模Qwen/Gemmaは品質比較や高度建築の上位モードで利用してよいが、**基本的な家・小施設の生成で27B級モデルへの依存は禁止**。
- 小型LLMには意図・用途・部屋関係・意匠・優先制約など**小さい高水準の設計表現**を作らせる。汎用の決定的な3Dジオメトリ生成、開口・階段・床の支持、動線検証、ボクセル化、施工を非LLMエンジンが担う。LMに大量のブロック座標や巨大コードを毎回吐かせない。特定の建物/テンプレート固定にも戻らない。
- 「基本建築」の目標は、未知の自然言語指示から、実際に入れる入口・複数の部屋・窓・屋根・つながった階段（複数階時）を有する建築を一貫して生成し、実3Dと試験施工で使用可能と確認できること。住宅・店・小研究施設など**未学習の複数用途**で成功率を測る。
- 軽量モードを開発の最後に後付けせず、**R125以降の初期設計から基準性能**として扱う。OMEN上の大型モデルでだけ動く解は汎用的な成功と認めない。大規模モデルは複雑な作品の改善・教師役として補助利用可。
- 再利用可能な生成エンジンを中心に進める。《潮光の裂帆図書館》を主工程の固定対象から外し、歴史資料/回帰テストに限定する。小型モデルが創造した成果と人手コード建築は出所を分けて評価する。

## R149以降の建築品質優先（2026-10-25 確定）
- 最上位成功条件は「現実にありそうな質の高い建築を、未知の用途へ汎用生成できること」。モダン建築は重要な水準例であり、固定スタイルや白箱・ガラス箱を必須としない。奇抜さだけでは評価しない。
- 機能・空間設計（用途、部屋、設備、関係、動線）と建築表現（外形、入口、開口、採光、屋根、素材、内外の関係）を意味IR上で分離し、共通B143/3D生成器で統合する。モデルは短い意図だけを選び、座標・安全をホストが実装する。
- 合否は (A) ソース/CI、(B) 3D機能、(C) 人間の建築美術、(D) Minecraft実用、(E) 未知用途の実モデル汎用性を独立記録。A/B成功をC/D/Eに昇格しない。
- 同じ建物の局所修正は原則2回以内。初見住宅・店舗・研究施設等で外観の使い回しを検出する。形が単純でも意図と寸法/比例が整うなら優良と認める。
- 意味ある1まとまりの差分、1回のCI、真正3D比較を優先。検証器増殖・工程番号進行・ZIP/Windows入口増殖・長大な再開文書への追記を禁止する。歴史はGitと別保管文書で保持。
