# MinecraftAIBuilder — AI継続開発憲章（固定方針）

**ここは長期間維持する原則。現在工程・HEAD・CIは [AI_RESTART_JA.md](AI_RESTART_JA.md) で確認する。**
B100時代の `docs/B100_START_HERE_FIRST.md` は歴史的資料であり、現在のR96時点の作業入口ではない。

## 目的・成功条件
- 自然言語で未知の建築用途・世界観・機能・立地・規模を受け取り、AI自身が独創的な外観・内部・空洞・階層・床・入口・昇降・家具・動線を同時に設計する汎用AI建築システムを実現する。
- 現物の実3D形状から美術・機能・幾何を別々に審査し、改善した上で、人間の別途明示承認があった場合だけMinecraft Educationへ安全に施工する。Java対応は後段。
- **最優先は建築としての独創性と美術品質、外形・内部・用途の一体性、使える空間**。JSON整形、形式的PASS、テスト本数、R番号増加は成功条件ではない。
- 現在の《潮光の裂帆図書館》はc01ベンチマーク用の **AIではなく人手/コード作成の独立3D美術研究**。汎用テンプレート化しない。他用途の生成能力やQwen改善の証拠にしない。
- 建築に使う形状、塔、リング、アーチ、曲面、浮遊床、材質などは先入観で禁止しない。箱の装飾だけ・閉塞した空洞・偽物の階段や経路では不合格。
- 正面/斜視/側面/俯瞰/内部/入口/主要室/上下動線を必要に応じて確認。美術は人の審査が必要で、ソースからの2D投影や数値PASSに置き換えない。
- **検証の区別：** (A) ソース/CIの整合、(B) 実メッシュ上の幾何・機能候補、(C) 人による美術品質、(D) 実Minecraft環境での可用性、(E) 実モデルの汎用生成能力。Aが成功してもB〜Eは自動昇格しない。

## 絶対維持する安全境界
```text
readiness = NOT_PREPARED
constructionApproved = false
executionAllowed = false
construction gates = 9 × BLOCKED
BuildPlan.operations = []
```
- 研究中の実Qwen/Gemma追加推論、Minecraft世界への接続/読取/書込/施工は0回を維持。過去の単発Qwen承認を再利用しない。
- モデル変更、実Qwen/Gemma高負荷実行、有料APIや課金、ユーザーPCのローカルWork/Computer Use、ゲーム内操作はそれぞれ**新しい個別の明示承認**が必要。
- mainマージ、PR #128のReady/Close/Merge、旧Freeze、B99/B100、凍結されたB143/Qwen原本の改変、強制push・履歴破壊は禁止。安全な研究ブランチへのコードコミット・通常pushは継続可。
- 保存済み実Qwen図書館原本のSHA256：`40810c69e56e59f61704ef0e0a1d96f98a2415aa057a86d7355c44421ab3edbf`。原本はB143 HOLD、構造・動線不成立。後年のアシスタント生成形状と出所を混同しない。
- 失敗・未審査はHOLD/NOT_REVIEWEDのまま保存する。原本の上書き・合格偽装・実行したふりは禁止。

## 品質・効率
- Chatと接続済みGitHubを基本とし、Workはユーザー承認があり明確に優位な場合だけ。Plusの利用量とユーザーの手作業を節約。
- 既存の継続ブランチとOpen/Draft PR #128を使い、小〜中規模で意味のある差分とコミットを積む。ZIP/CMD/ワークフロー/再認証を工程ごとに増殖させず既存R60レビュー経路を再利用。
- PR/pushの軽量テストとworkflow_dispatchの完全回帰を区別。省略・キャンセル・失敗を隠さない。
- 現実の不具合を優先し、検査だけの開発に戻らない。Minecraft未施工のまま改善成果を3D証拠と共に記録。
- **引き継ぎは毎日書き直さない。** 工程が実質的に進んだコミット時のみ [AI_RESTART_JA.md](AI_RESTART_JA.md) の「確認済み現在地/次工程/重要ブロッカー」を最小更新する。長い履歴は既存R番号別docsとGit履歴で保存。記載されていない新事実はGitHubで検証する。
