# R190-BL — 元の要求を見ながら真正3Dを比較する（品質評価の実験準備）

基準：2026-10-30 JST。継続Draft PR #128、ブランチ `feature/b198zr1-protected-architectural-revision`。施工・新規Qwen/Gemma推論なし。ART HOLD、正式採用0。

## 何を改めたか
R190-BCは用途・利用者・空間体験を先に考え、R190-BJは過去の実Qwen原文（不正B143、階段軸・入口・支持床・頭上空間の矛盾）から自己整合チェックを追加した。しかしBF/BE/BG/BKで合成通信試験がPASSしても、モデルが元の依頼に合う良い建築を実際に考えたかは不明。さらに、従来BKは元の日本語依頼そのものを表示せず、3D・投影ファイルもBE生成時のバイトSHAと照合していなかった。

BLは**新しい評価器や固定の建物を追加せず**、既存比較の入口で実際の原文・真正ビューを合わせて確認できるようにする。

1. BF比較が既存の準備済み元日本語依頼のバイト列をSHA照合し、比較フォルダーに `R190BL_ORIGINAL_BRIEF.txt` として改変せず保存。BF報告 `R190BF_CONTROLLED_PAIR.json` に元原文SHAと、BEが生成した真正3D・五方向SVG・断面SVG/JSONの各保存バイトSHAを記録する。
2. BKは元依頼とBE比較原文のSHA一致を確認し、元の日本語依頼をHTMLエスケープして表示する。候補A/Bの真正3Dと五方向投影・断面に直接進める。
3. BKはリンクするビューのSHAをBFに保存した値と照合する。改変画像・切断した3D・偽造した元依頼があればBK出力を生成せず拒否する。
4. 元B143が無効ならBI/BH診断を提示し続け、存在しない3Dを補完しない。BG人間審査も両側の原形状が有効な場合のみ表示する。

## R190-BL以降の本物の美術評価手順（事前固定・未実施）

実モデル応答を使う前に、ユーザー自身の未知の日本語依頼を一切要約・改善せず固定する。モデルAは元依頼を直接B143へ、モデルBは同じ元依頼を設計先行（BCまたはBJ）へ変換する。**BCとBJは異なる指示案であり、同じ比較試験ではない。** 比較方法の切替は事前に明記する。temperature/seed/maxTokens/モデル要求値/同一システム指示は記録するが、提供側のdigest・sampling・ランタイムが実際に同一であったことは独立確認できない。

一つの建物を検査するときの「成功条件」は以下をそれぞれ別判定とし、形式上のPASSで次を推定しない。

| 評価の階層 | 実際に見るもの | 不成立の扱い |
|---|---|---|
| モデルの著作性 | 原文のdesign・spatialPlanと完成B143の一致 | ホストで形を補ったならモデルの成功にはしない |
| SOURCE機能 | B143契約・床支持・立脚空間・入口・開口・利用空間・断面・動線 | 多層移動・実Minecraft歩行は検証しない限り未認証 |
| 用途と体験 | *元の日本語依頼* を読み、使う人・目的・空間の質を元3Dと視点で評価 | モデルの用途宣言だけを適合の証明としない |
| 建築美術 | 遠景輪郭・主空洞と質量・屋根/床の統合・内部体験・独創性を人間が比較 | 直方体の微修飾、材料変更、CI件数増だけでは採用しない |

既存BGの4基準（用途と利用者への適合、内部体験、質量/空洞/屋根/支持、独創性）を再利用し、**数値差で勝者を自動選定しない**。実モデルが１組だけ改善しても汎用性・因果関係の証明にはならない。未知の用途や複合要求を複数の独立課題で後に確認する必要があるが、試行数や用途を恣意的に選んでよい結果だけ報告してはならない。人間評価は非盲検の可能性があり、その限界も明記する。

## 利用方法（推論なし）
既にBFで比較が完了した`NEW_COMPARISON_DIR`に対し、従来と同じ1回の操作でBK画面を生成する（**BL以降に作られた比較結果のみ**元原文・画像SHA情報がある）。

```powershell
node scripts/r190bk-evidence-stage-review.mjs --compare NEW_COMPARISON_DIR
```

生成された `R190BK_EVIDENCE/R190BK_REVIEW.html` で依頼と真正ビューを確認する。元原文は比較フォルダーのローカルデータであり、自動でGitHubへ公開するものではない。保存済みの古いBF比較については、ハッシュのない見本画像をBLで保証したものとして再ラベルしない。
