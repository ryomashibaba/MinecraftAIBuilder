# MinecraftAIBuilder — Compact ArchitecturePlan から真正3Dまでの最短縦貫計画

基準：2026-10-31 JST。対象：既存 Draft PR #128 / `feature/b198zr1-protected-architectural-revision`。上位正本は `docs/AI_PROJECT_CHARTER_JA.md` と `docs/PROJECT_STRATEGY_V2_JA.md`。この文書は新しい長期憲章でも固定R番号ロードマップでもない。現在の実測失敗に対応する、退出条件付きの実装計画である。

## 1. 出発点と厳格な結論

実Qwen3:14bの直近の建築依頼は、HTTP 200 / 42秒程度 / `done_reason: stop` / 入力953・生成2101トークン、思考欄空、JSON構文成立。BN は `R190BN_LEVEL` で HOLD。外寸高さ8に上階 `standingY=9`、階段の説明はあるが階段操作がなく、空洞を再充填する操作や範囲外入口が報告された。**正確な生HTTPと原回答のバイト列はユーザーPCの非公開保存物にある。GitHubには存在しないため、この設計からその原文全体が解析できたとは言わない。**

これで通信やトークン上限を伸ばすだけの議論を終え、**モデルが創造的な意味設計を行い、決定論的な共通コンパイラが幾何の算術を担う**という既存戦略v2へ戻す。ただし実モデルが設計したものをホストがこっそり直して成功させてはならない。完成した自然言語回答・JSONの合格と、使える3D建築の合格は違う。

## 2. 不変の成功条件と厳密な独立ゲート

- A ソース：正規IR、出所・SHA、安全・再現性、コンパイルの一貫性。
- B 真正形状：非空のB143最終ボクセル、床の支持、頭上空間、屋外からの入口、機能ゾーン、必要なら階段と連続する上下動線、窓・屋根・外壁の実幾何。単に形状名があるだけでは不可。
- C 美術：人間が真正3Dの正面・斜視・側面・俯瞰・入口・室内・階段を同条件で見る。箱の反復、偽の巨大装飾、外観と内部の不一致は拒否できる。CIによる自動ART PASSは不可。
- D ワールド：別の安全アダプタで識別済み試験ワールド、バックアップ、差分、実施工、実歩行、復元が確認できた時だけ。現段階のBN/B143は世界未接続・9 BLOCKED・空BuildPlan。
- E 汎用LLM：実Qwen/Gemmaが異なる未知の依頼で建築意図を独自選択したことを原回答とともに確認。ホスト派生の代作や合成fixtureを成功数に含めない。

最上位指標は **初見モデル依頼 → 作者のArchitecturalPlan → 真正B143 → 実利用・美術審査への到達**。生成されたJSON数やCIテスト数で代用しない。

## 4. Compact ArchitecturePlan v1 — 第一歩として実装した検証境界

ソース：`source/ai/r190bn-compact-architecture-plan.mjs`。これは**純粋なauthor-contract検査**で、3Dコンパイルを主張しない。モデル選択値とホスト算術値を明確に区別する。

- `schema,id,title,originalBriefSha256`：元依頼SHA照合。原文は別に不変保存。
- `site:{width,depth,height}`：モデルが規模を選択。B143制限内。追加の絶対ワールド座標は持たない。
- `stories:[{id,clearHeight,spaces:[{id,purpose,width,depth,privacy}]}]`：立脚yをモデルに手書きさせない。コンパイラは**モデルが選んだ階高**から `standingY[0]=1; standingY[n+1]=standingY[n]+clearHeight[n]+1` を算術導出。存在しない階は増やさない。
- `adjacency` / `entry` / `verticalLinks`：必要な接続関係・入口面・作者選択の階段形式（straight/switchback/spiral）、側面、幅。2階建てのリンクがなければ受理しない。螺旋のような実装未対応選択を直線に置換しない。
- `massing` / `roof` / `openings` / `materials`：用途別固定テンプレートにしない。特徴種別は増強可能な語彙として保存し、未実装の幾何を実装済みと偽らない。作者の建築表現は説明文だけで代替しない。
- `assumptions,unmetRequirements`：モデルが実装不能や取りこぼしを正直に宣言。欠落した要件を無言で捨てない。

制約：今のv1検証器は、参照ID、階の連続性、部屋寸法、上階の成立範囲、隣接/入口/階段、主外形・素材の欠損を防ぐ。**空間の物理的な配置可能性・窓が本当に外に面するか・階段を歩けるかは未検査**。`contract=VALID_AUTHOR_CHOICES_GEOMETRY_NOT_ATTEMPTED`、`geometryCompiled=false`、9 BLOCKED、ART HOLDを明記し続ける。

注意：これは現行のBN入力を無理に短くしたものではない。新形式に作者の明示値がある時だけ、新しい deterministic compiler がそこからBN/B143を作る。旧失敗原文を『新形式で成功した』と読み替えない。

## 5. 実装の次の3段階（工程番号の増殖ではなく成果で退出）

### 段階I：IRの独立検証を成立（このコミット）

- 既存の保存済みQwen/Gemma証拠とGitHubを改変しない。
- 要求→ゾーン・上下関係・外形/屋根/窓の選択を持つ作者入力を厳格検証。初見アトリエと、別用途の合成反例に共通契約を適用。2階リンクなし・高さ超過・不正参照・形式不一致はHOLD。最初はデータ構造6ケース程度で足りる。
- Node 22+（CIはNode24）、既存CIに一箇所だけ接続。モデル通信0、ワールド接触0。3D、C、D、E成功を主張しない。
- **退出**：契約検査と不変原本・出所を確認できること。

### 段階II：既存BN/B143を使う汎用2層縦貫（次の実装）

- 既存R190意味設計器の**配置の考え方（room graph + bounded placement）**と、BNの**enclosure/flight/B143**を再利用。意味→幾何の接続部分だけ新実装。システム全体の二重実装を避ける。
- まず「下階の公共空間→外入口→モデルが選んだ階段→上階の用途空間」という、**実際の2階空間・階段を含む縦貫パス**に限定。モデルが必要な高さ・階段経路・寸法を指定し、決定論的ソルバーが位置を計算。梁・床・屋根・開口は生成したB143の最終占有から測る。
- 上階の床と下階の屋根／階段周囲の床開口、階段の上下立脚点、外部からエントランスへの動線を**同時に**制約処理する。中空外皮を先に作り、巨大ADD→CUTの途中16万セル制限を避ける。部材同士の上書き順で意図した空気を閉塞させない。
- 作者が `spiral` や `freeform` を選んだ場合、真の幾何を実装していない限り `HOLD_UNSUPPORTED_AUTHORED_FEATURE`。任意の曲面を黙って箱に置換しない。まず対応できる設計表現の能力範囲を正直に示す。
- 支持床100%・作者指定のclear air・外入口2セル・階段上/下の連続立脚点・両用途到達・床抜けなし・屋根/窓の実体を検査。R4は単一セル到達の代理指標であり、実Minecraft歩行と区別。
- 代表の合成ケース1件は、**ソース→実ボクセル→5正投影・3近似視点のCE**まで接続。別用途1件は回帰として使用。モデル生成成功とは数えない。実現不能ケースは3DなしのHOLD。
- **退出**：モデルの自由な入力が構造制約の範囲内で、作者意図の変更なしに実2階3Dへ変換でき、類型固有テンプレートやfake PASSがないこと。

### 段階III：実モデルの最少回数再検証（段階IIのPASS後）

- ユーザーの初見日本語依頼を変えずに、**同一の実Qwen3:14b**を短いIRでまず1 POST。既存のBOローカル-only、原文保存、SHA固定、think設定、個別のexact SHA+nonce承認、再送0と失敗HOLD契約を保持。旧BOの型を使い回して成功したと偽らない。
- 送信前にNode標準HTTP経由の読取専用GET・Ollamaモデル同一性/メモリ/応答時間を確認。接続確認はPOST成功保証ではない。新しいschema/sourcePinsを含む**新しい個別承認**が必要。古い試行ロックの再利用禁止。
- 同じQwenでまず原回答がコンパクトIRとして完成するか。成功しても3D・階段・床・空気・窓/屋根・美術を別ゲートで判定。不能ならモデルを無理に再送せず、欠落項目に応じてIR契約かソルバーを汎用修正する。
- Qwen結果を分析してから同一条件でGemmaを個別承認付きで実行。さらに住宅/店舗/研究室という異なる用途と改修で汎用性を評価。単一例から成功率を推定しない。
- 初回が成立した後に、小型Mac 8GB級/2Bモデルの省入力・省メモリに同じIRを活用（別実機ベンチマーク）。
- **退出**：実モデル出所の未改変IR→真正3D→実機能の可否と人間美術審査に到達。Minecraft施工は別のバックアップ・ワールド特定工程に移す。

## 6. 事前の批判的レビューと修正

1. **『座標を隠しただけで箱テンプレート化するのでは？』** — その危険はある。モデルが選ぶ主外形・屋根・窓・上下吹抜/光・素材・室関係が**実3D**へ反映されるかを合否にする。未実装形状はHOLD。単なるテキスト意図・外壁装飾だけを完成扱いしない。
2. **『ホストが位置を決めれば作者の創造性が消えないか？』** — コンパイラは幾何的成立条件を満たす座標を算術選択するだけ。ゾーンの関係、階数、階段形式・側、外形・寸法の作者値を変えてはならない。別のレイアウトを採用するなら作者が指定した関係を維持し、派生版のSHAを別記録する。
3. **『2階アトリエへの過学習では？』** — 受け入れテストは初見アトリエ1、未知用途の合成反例1、用途変更1。物理アルゴリズムにはアトリエ・住宅・図書館などの分岐を入れない。
4. **『モデルの自由な曲面、螺旋階段は？』** — v1で未対応ならHOLD。将来の能力を最初から禁止はしない。最初の3D成功が直線階段だけでも、全自由設計達成とは呼ばない。
5. **『モデルに必要な具体値を渡す負担はまだ大きいのでは？』** — プロンプトの二重Schema説明、各ボクセル座標、無意味なquality thresholdを廃止し、必要な室幅/深さ/用途・関係のみ。原回答トークン長と妥当性は実測して比較する。
6. **『安全のため新たな承認を繰り返すのは面倒』** — コードに保存された個別承認ゲートと、上位憲章の包括許可に不整合がある。現行BO送信経路では勝手に弱めない。準備・通信なしQA・原本監査を一括化し、個別承認が必要な送信境界だけ人間に確認する。

## 7. 効率制約と最初の意思決定

- **追加するのは契約1ファイル + テスト1ファイル + この短い決定ドキュメントだけ。** CIは既存R190-BOジョブに相乗り。既存main・凍結原本・旧Qwen応答・既存PRを改変しない。新しいブランチ・zip・PowerShell入口は作らない。
- 3Dソルバーは次の独立した**一本の縦貫実装**として作り、連続する小修正でテストを増やし続けるのではなく、幾何・負例・画像までまとめて検査する。
- この段階は**ArchitecturePlan検証器のみ**。`geometryCompiled=false`、`ART_HOLD`、新実モデル推論0、Minecraft接触0を必ず表示。次工程の成功を先取りしない。
- 今後の失敗がパーサの形式なら契約を直す。作者選択が幾何学的に不可能ならHOLD。技術成立して美術が悪ければIRの創造性/表現能力を再評価。課題の種類が違うのに同じ外形なら汎用性不合格。
