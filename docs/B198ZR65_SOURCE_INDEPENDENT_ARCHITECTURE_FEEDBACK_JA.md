# B198Z-R65 — 全館ボクセル検証を設計改善指示に実証的に接続

対象：Draft PR #128。R64の両OS CI PASS後。実Qwen呼び出し・Minecraftワールド操作は一切実施しない。

## 具体的な改善
R62はモデル自身が宣言したspatialPlanと原本に現れる問題から将来の改善指示を作れるが、モデルが都合のよい部屋しか申告していない場合は、階上の孤立空間や全館にわたる狭い通路を見落とす。R64ではspatialPlanに一切依存しない全館の支持床・2セル頭上空間・抽象連結成分を数えた。R65では両者を統合する。

## 信頼境界
- 新規 `scripts/b198zr65-independent-network-feedback.mjs` は入力R64 JSONの原本SHA、最終概念ボクセルgeometry SHA、形式フラグを調べるだけではなく、**保存原本からR64をもう一度算出し、metricsとpossibleSpatialConcernsを厳密照合**する。偽造された集計値はHOLD。
- R65で新しいAI設計は生成しない。建築品質の自動合格、施工準備完了、モデルへの自動再呼び出しは絶対に行わない。原本・形状の修復も行わない。
- B143 PASS時のみR64をR62へ渡す。B143 HOLD時はR51の未コンパイル外接形状とR62の形式不備だけに限定する。

## 改善指示への反映
- 支持床・頭上2セルを持つ候補が全くない：建築全体に実際に使える空間があるか人間が優先確認。
- 低層候補とつながらない上層の床：観察ラウンジや上層公的空間への連続性、着地点、階段・ランプ等の成立を調べる。しかし意図された独立建築や浮遊構造を単に潰したり連結したりしない。
- 抽象移動が多成分に分離：ホール、翼、階層のアクセスを点検。建築的に意味のある分離は維持。
- 2x2床上空間が無い：用途上の室内・通路・踊り場の幅を調べる。ただし2x2条件を満たすためだけに空の床を追加しない。
- これらはAIが申告した区域のR61チェックとは証拠の由来が異なる。すべて人間の確認が必要で、元の美術構想や建築質量の縮小を自動的に促さない。
