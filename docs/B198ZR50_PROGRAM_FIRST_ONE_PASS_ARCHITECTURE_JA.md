# B198Z-R50 — プログラム先行・一回応答の建築設計（研究候補・実推論なし）

## 対象

R49はWindows/Ubuntuの最終CIをPASS。R48の実`qwen3.8:27b`ではJSON Schemaが型違反を減らした一方、屋根・階段4要素が範囲外、入口から目的地までの宣言上限4件が数学的に不可能、吹抜け・左右書架空間の埋戻し、目的地IDの重複など、建築実態の自己矛盾を起こした。R48の承認は消費済み。

**R50はモデルの建築発想とソースの一体性を改善する未来候補を開発する。今回の実Qwen推論は0、Minecraft施工/接続0。**

## 建築の発想を操作順序に変える

`source/ai/b198zr50-program-first-architecture-guide.mjs` は「箱を並べて名前をつける」アプローチを改め、モデル自身の**一回の出力内**に以下の順番の空間設計を求める。

1. 依頼固有の「内外を統合する1つの建築的着想」と、各階/用途でどんな空気領域が必要か。
2. 実際に立てる床、入口、回遊路、上下移動、階段の上端・下端、各階の着地点。どの経路も形状と整合。
3. 着想を反映した外形：要求に合うときだけ曲面/非対称/テラス/梁を活用し、建物質量の大局構成を優先。**特定の形状を一律に禁止・義務化しない**。
4. B143の厳格ソリッド/空気（ADD/CUT）を最終操作順序で確認し、必要な部屋・本棚・吹抜けを現実に作る。
5. `spatialPlan`には最終状態で成立する入口・目的地・空洞・機能領域を正直に宣言し、計算不能な到達上限を設定しない。

R49の数学的下限は「水平マンハッタン距離」と「高さ差」の**最大値**。R3では横移動と1段上下を同じ歩行ステップで実行し得るので単純和は不正確。B143 boundsの上端は**排他的**、階段最終端とrepeat最遠端も含む。

単に説明文で「書架」「星空ラウンジ」と書いても本棚ソリッド/機能する歩行空間にならない。R50は外部、内部、動線、用途が同じ幾何として成立することを要求するが、**実際に実現できるかは未検証**。

## プログラムの独立性

`r50HumanIntentPacket(caseId)` は凍結済みB198Bのc01〜c12全12ケースから、ユーザーの元の日本語依頼と、人間の視覚/意味評価を必要とする4前後の基準を読み出す。モデル自身が都合のよい`spatialPlan`閾値を設定しても、本来の「図書館」「港」「寺院」「美術館」等の要求を上書きできない。

これは設計案の自動生成や型別テンプレート化ではない。寸法・座標・マス/ブロックの固定配置は挿入しない。`r50HumanIntentPacket`の内容そのものを実モデルが受けて品質改善した証拠もない。
