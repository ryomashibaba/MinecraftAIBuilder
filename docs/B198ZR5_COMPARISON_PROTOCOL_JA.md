# B198Z-R5 — 元QwenとR4の公正な比較を可能にする実証基盤（2026-10-19）

## 目的とこの工程で成立した事実
これまで R1/R2 で人手修正例を作り、R3で独立した空間動線監査、R4でモデル自身の空間計画とB143形状を**1応答**にする任意形式を実装した。R5はその成果が**本物のQwenの生成品質を改善したか**を判定できる材料を作る工程。

現在、**R4の実Qwen原本はないため、改善した／悪化したの結論は出せない**。合格だけが増える形式的QAや人手R2の偽装比較に戻らない。

## 凍結された原本
元の `MinecraftAIBuilder_B198Z_COMPLETE_HANDOFF_20261019.zip` の `EVIDENCE/B198U_ORIGINAL_MODEL_RESPONSE_UNMODIFIED.txt` は **3,397バイト**、SHA256 `40810c69e56e59f61704ef0e0a1d96f98a2415aa057a86d7355c44421ab3edbf` で、2026-10-19に現物バイトを再照合した。原本そのものは編集しない。図書館c01、Qwenモデル名 `qwen3.8:27b`、14要素、約88.748秒で生成した事実は引き継ぎ記録によるもので、提供者の認証署名ではない。

モデル原本は B143 `OUTSIDE_LOCAL_BOUNDS` により棄却済み。これを黙ってbounds延長しR4と同列の「生成功例」にしない。`evidence/b198zr5/c01_original_capture_manifest.json` にキャプチャの状態を記録。R4原本は存在しないので未取得と明記する。

## 実装
- `source/ai/b198zr5-model-comparison.mjs`: 保存した **baseline 3項目** と **R4 4項目** を、同じB198B凍結課題・同じ4評価観点で分析する。人手ソースは比較適格から明示除外する。実Qwenキャプチャの真正性については利用者申告以上の保証を付けない。モデル識別子が異なる場合は同じプロンプト手法の比較として認定しない。
- ソース構文、真のB143コンパイラ、幾何ハッシュ、B198Wの独立幾何監査、R4のモデル宣言空間計画を別々に検証。未コンパイル、後から埋まる吹抜け、履歴ソース改ざんは HOLD。
- 人間が 3D/断面を見て入力する **元のB198Bの4つの観点（各0〜4）** は同じ内容で固定し、両元ソースのSHAと一致していることを確認。レビュアーが入力したという事実はモデル自身の評価と区別し、提出があってもモデルの優越の自動証明はしない。
- 完全でない記録でも正直な `HOLD_MISSING_SAVED_MODEL_PAIR` レポートを作成できる。**R4データを捏造しない**。
- `scripts/b198zr5-compare-captures.mjs`: オフライン単一コマンド。モデルのロード/再実行、Minecraft施工/接続、課金API、Workは行わない。既存レポートの上書き禁止。

## CLI：実モデルを呼ばずに旧原本を監査
引き継ぎZIPを既に解凍済みで原本が手元にある場合の参考。ユーザー操作は現時点で**不要**。

```bash
node scripts/b198zr5-compare-captures.mjs \
  --case c01 \
  --baseline /path/to/EVIDENCE/B198U_ORIGINAL_MODEL_RESPONSE_UNMODIFIED.txt \
  --out /path/to/NEW-R5-baseline-preflight.json
```

R4原本が無いため **exit code 2 = 正しいHOLD**。レポートが生成されているかで判定。必要になったときだけ `--r4`、両原本にピン止めした`--baseline-receipt`/`--r4-receipt`、`--baseline-human`/`--r4-human` を追加する。

## 比較の公平性に対する制限
- ケース c01〜c12 を `source/ai/b198b-benchmark-cases.mjs` からのみ選択。形状テンプレートへのマッピングなし。
- 真正な「両方を同モデルの同じ条件で実行」という認証は、単に保存されたJSON/申告レシートだけでは証明できない。**モデル設定の同一性・モデル実行の真偽を独立保証したことにはしない**。
- R4 は4項目となるためトークン消費の違いが出る。最大出力長や実応答時間を次回試験で記録し、数値だけで優越判定しない。
- R1/R2人手改修例、R4 HTTP mock/テスト用パビリオン、過去の旧Legacy建築はモデル性能比較の分母・勝敗に絶対含めない。
- 人の評価でも1事例に過ぎなければ、他ジャンルで汎用改善したと断定しない。十分な異種ジャンルに段階的に拡大する。
