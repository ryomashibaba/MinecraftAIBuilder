# MinecraftAIBuilder — 5ジャンル横断ARTと建物全体外形能力の次工程（2026-11-03 JST）

## 0. ユーザー真正SOURCEの画像と数値からの判断
2026-11-03の `COMPARISON_REPORT.json` とユーザー提出の同一縮尺の正面/側面/俯瞰画像を分析。平屋住宅1,138実ボクセル/4室、独立店舗661/2室、研究施設1,025/4室、小美術館1,584/4室、小駅舎894/3室、**5/5でSOURCE経路成立**。最初の4モデルは元SHA一致、駅舎は旧寸法7..14によるHOLD履歴を維持したまま汎用6..14によって元原文からSOURCE再コンパイル。追加推論0、worldWrites0。
画像では5棟すべてがほぼ平坦な矩形または直方体の集合で、用途の違いが外観や室内の機能表現として成立していない。正式多視点ARTとは別の**比較画像に基づく暫定ART HOLD**。5/5 SOURCE成功を建築品質の改善と取り違えない。

コード・レポート双方で確定した共通の技術制約：
1. 各室の屋根は独立した水平B143直方体で、モデルは屋根断面を独立指定できない。
2. 外壁窓は共通HOSTが原則各室最大1グループを決定し、採光と機能に基づく構成は設計IRにない。
3. `purpose` は意味的な用途文字列にとどまり、家具・展示設備・レジ・観測機材など真正B143が未生成。

**住宅専用/駅舎専用の屋根パターンを決めることは禁止**。最も大きな共通制約から、モデルが抽象的な屋根の断面/方向/上昇量を自身で決定できる新設計経路を独立させ、実際の屋内利用可能体積も変化させる。独創的な完成建築ではなく、5棟共通の外形表現力を試す第一段階。次は空間プログラム・開口/室内機能の一体的な設計を拡張する。

## 1. v2研究IRと真正3Dの必要条件
- 旧 `r125-spatial-composition-v1` 原本の意味/3D/5件SHAを変更しない。別の `ENVELOPE_SCHEMA=minecraftaibuilder-r125-author-envelope-v2` が `planId` と全ての `rooms` ごとの `{roomId,form,axis,rise}` を**著者が明示**する。使用語彙は一般的断面演算子の `shed` / `ridge`、方向 `x` / `z`、上昇 `1..3`。HOSTが用途名で形を割り当てない。テストで作る著者入力は本物のQwen著作と認定しない。
- `source/ai/r125-expressive-envelope-v2.mjs` は旧v1 TRUE B143を検証した後、**水平屋根直方体だけを置換**し、モデルが選んだ断面に従う屋根面・軒下の外壁の上部・段差の閉鎖を新B143ボクセルとして形成する。上に偽装飾を被せた天井は不採用。元の窓、入口、用途空間/床と室間接続の意味を保護。
- 元屋根を占めた位置に実際の空気空間ができるか、各室の2×2連続頭上空間が本当に増えたか、真正B143表面が閉じているか、入口から全室SOURCE経路が成立しているか、既存ボクセルと比較。失敗はHOLD、修復・モデル差し替え・ワールド書込は禁止。
- 5室の大きな研究設計も要素数160と既存B143安全バジェット内のみ受け入れる。 `NOT_PREPARED`、9 `BLOCKED`、BuildPlan空、model authorship未証明、Minecraft未実施工、ART未認証。

## 2. 5ジャンルのモデル独立著作
- `scripts/r125-five-genre-real-envelope-pilot.mjs`：ユーザーの私用フォルダ内の保存済み5Qwen原文と別の診断レポートをSHA照合。**元の平面案は生成し直さない**。各ジャンルに同一の独立設計契約で、モデルに屋根の断面形状/方向/上昇量を1件ずつ著作させる。ローカル `qwen3:14b` への5推論は逐次実行。一次原文/SHA保存、推論の再試行なし。
