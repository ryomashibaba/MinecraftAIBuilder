# R29 — R27実測失敗とR28指示の対応監査

## 判定
**R28の静的な指示カバレッジは10/10**（ただしモデル改善の実証ではない）。新しい実推論・実施工を承認しない。

## 対応したR27実測
| R27観測 | R28での対策 |
|---|---|
| CUTの材質規則違反5件 | CUTはmaterialを完全に省略 |
| base-shellが中実58,080セル | BOXはshell/CUTがなければ中実と明記 |
| 左読書領域1,200/1,200占有 | 家具と利用可能な立ち位置を区別 |
| 右読書領域1,200/1,200占有 | 同上 |

| 立ち位置が6つの連結成分に分断 | 入口から各目的地への接続 |
| 概念立ち位置合計256 | 接続した支持床・空気セルで利用領域を定義 |
| 最大成分100 | 利用施設全体への到達を要求 |

## R29で新しく特定した指示側の2つのリスク
1. **過去の座標を一般規則に混ぜる危険**：R28に含むz=45/z=44の具体例は、モデルに固定座標を連想させる可能性がある。将来は「開口が入口からの連続経路と位置・高さで交差する」と一般化する。
2. **経路が1本だけという過剰制約**：「Design ONE continuous abstract route」は、任意の接続ネットワークより狭い読み方を招く。入口から全目的地へ到達できることを条件とし、経路本数はモデルの建築案に任せる。

## 対応判定の限界
この監査はR27実測としてユーザーが共有した項目と、R28ガイドの文字列を照合する**静的検査**。実際のR27診断JSONをこのコードに取り込んで再計測したわけではなく、Qwenが指示を正しく実行できることも意味しない。人間が理解できる計画と最終概念ボクセルのR3検査は別物。

次工程R30は、凍結R28ガイドを維持したまま上記2点を一般化した**新たな未有効化候補**を作り、無理に複雑なテンプレートを押し付けずトークン量と安全性を確認する。

安全条件: R25承認消費済み。実Qwen呼出し0、ワールド接続0、読取0、施工0。NOT_PREPARED、9ゲートBLOCKED、BuildPlan.operations=[]。
