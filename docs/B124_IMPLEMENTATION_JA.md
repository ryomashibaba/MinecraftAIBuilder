# B124 — 階段・廊下・床開口の3D独立監査（施工なし）

## 経緯

B122のOFFICE_V1階段#6候補は延べ82通路セル・B114仮廊下2セル再配置を必要とし、B123で全15棟102階段の「幅2の既存ネットワークに新たな断線を作らない」ことを限定2D代理モデルで確認した。本工程では、この候補の3D接続境界に残る床支持・頭上空間・階段部材との干渉を実データで再確認する。

## 実装

1. B121/B122/B123/B117のSHA256整合性を検査し、全15棟66階102階段と同一候補を再構成。
2. 独立した3D AABB検査により上下2セル幅の廊下全長の人体代理空間（高さ2ブロック）を走査する。
3. B105ソースボクセル、再構成した候補階段の踏面・踊り場・支持材、他階段の踏面・支持材の3D干渉を分類する。
4. 上階床Y=(階+1)×5と階段身体代理形状の交差セルを計算し、上階着地点2セルを保護したまま必要な仮想床開口を算出する。
5. 床開口が保護室・元廊下・他階段仮開口・新通路と交差しないか検査し、上下2レーンが隣接する連結部の有無を検査する。
6. 判定理由、衝突セル、床開口候補をJSON/CSV/日本語レポートに保存する。
7. 8反例テスト＋5全棟統合/安全テストを専用CIで実行する。

## 大事な境界

- プロキシ形状が干渉しなくても **Minecraft Educationでのブロック状態・階段を実際に歩けるか・扉・踏面の細かな衝突・実床支持荷重を証明しない**。
- B105は設計用VoxelIRであり、実ワールドの測量データではない。
- 施工用BuildPlanや実ワールド座標を生成しない。B124の検証で元の9出口HOLDを解除しない。
- 明示されていないBlockStateを推測したブロック配置を行わない。
- CIが成功しても本工程が扱った限定代理モデル上の判定のみ。
- NOT_PREPARED / 9 BLOCKED / BuildPlan.operations=[] / worldContacts=0 を厳守する。

## 次工程選択

B124に新たな3D HOLDが検出された場合は、該当セル・保護室・上階開口と廊下の位置関係を元に限定的な設計変更案を作成する。新たなHOLDがなければ、Minecraft EducationのBlockStateパレット仕様・階段の半ブロック接続・扉・支柱支持の実認証準備へ進む。いずれも現行の施工HOLD解除は認めない。
