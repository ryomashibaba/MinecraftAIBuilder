# MinecraftAIBuilder B141 — 共用廊下・階床接続・上階開口の統合

## 目的
B140までに15棟・66階床・102階段のうち70件に、個別の5-rise階段と両端の幅2廊下を追加設計した。残る32件は引き続きHOLD。
B141では70件を独立した案のまま放置せず、建物・階床単位で統合して重複を解消し、入口からの幅2の概念経路と3D干渉を分析する。Minecraftでのユーザー操作や新しい実機テストは必要としない。

## 実装した具体機能
1. B113/B138/B139/B140のソースハッシュと実データを凍結ソースから再検証し、15棟の正規階床と102階段のみを対象とする。
2. 70件のB140階段別の上下廊下ブリッジを、階床ごとに座標一致で統合。元のソースgalleryとB113加算修復セルはすべて保持。追加セルの重複を取り除き、共用されるセルを記録する。
3. 元の部屋・階段コア・床プレート外に廊下を設置する案を拒否。連続する2x2通路の辺共有を確認して、曲がり角で幅1に狭くなる構造を排除する。
4. 統合されたギャラリーの2x2正方形をグラフのノードとし、隣接正方形とB140の上下階段をエッジで結ぶ。地上階の元exitから概念的にどの階に到達できるか計測する。
5. 70階段候補のオーク階段ブロック＋頭上2ブロックの保守的な3D占有検査を実施。上階スラブで開口が必要なセルを重複排除し、元の部屋・元gallery・今回の新規廊下に重なる場所を列挙。
6. 元から保留の32階段を、7x2の場所不足と、両端2列廊下・2x2ルート不足に分類し、次の構造再設計作業に結びつける。

## データの正しい読み方
本工程はオフラインでの**概念的な共用廊下ネットワーク**。元の建物の出口に到達することを概念グラフで推定しても、Minecraftの当たり判定、ドア開閉、実際の階段の支持材や上階開口の施工許可を証明したことにはならない。
特に、B136で実機PASSした3段とB137で視認上問題なかった6ブロック上昇のテスト経路を、5ブロック階床差の102階段へそのまま転用しない。
階段同士の3D頭上空間は保守的なグリッド方式であり、実際の半ブロック形状や物理衝突を独立に検証したものではない。
元の設計・部屋・コア・ワールドは一切変更しない。9件のBLOCKED、NOT_PREPARED、BuildPlan.operations=[]、main未変更を維持。

## 検証と成果物
GitHub Actionsが単体テスト、凍結ソース整合性、15棟実データ一括再計算、施工許可ゼロを確認する。
成果物は B141_15Buildings_Shared_2Wide_Network.json と B141_NETWORK_INTEGRATION_JA.md。
Windowsでの手動実行やMinecraftチャット操作は不要。

## B142以降
共有廊下のネットワークがわかったので、次は上階の穴と必要な支持材を実際の5-rise階段構造に組み込み、他の階段や廊下に干渉しない配置を共同最適化する。32件のHOLDについては別ルート形状（折返しなど）の本格設計を検討する。
