# B140 — 15棟・102階段の幅2廊下ブリッジ自動設計

## 目的
B139では5ブロック上昇の階段78候補中、両端で幅2廊下に直接つながったのは1件。予約なしの24件でも両端の直接接続候補は1件だった。
そこでB140は階段と既存ギャラリーの間の欠落を、**幅2を維持した曲がれる廊下**の追加設計で埋める。
B136の単一3段の上り下り実機PASS、B137の6ブロック下り記録と視認上問題なしを再利用する。B137のUP計測は未判定で、実験用6-rise経路を元の5-rise階床に直接転用しない。

## 実装

1. B113/B138/B139の凍結設計を再生成・検証し、15棟/66階床/102階段のソースを使う。
2. 元の部屋・他のコア・階段7×2のfootprint・床プレート外を廊下候補から除外する。
3. 階段の下側と上側に2セルの進入先を作り、DijkstraでB113の元ギャラリー・加算修復ギャラリーの**2×2正方形**まで経路探索する。
4. 正方形は隣の正方形と2セルの辺を共有するため、曲がり角でも幅1にはならない。必要な追加廊下セルを最小化する。
5. B138で既存予約を持つ78階段は元の位置を優先。そこで廊下が接続しない場合のみ、部屋とコアを守って別の7×2の階段位置を探索する。
6. B138で予約がない24件も同じ探索を適用し、両側廊下へつながる具体的な追加セルの配列を生成する。
7. 階段同士の同一3Dブロック座標での衝突を数え、建物ごとの独立案をJSONと日本語要約で出力する。

## 安全性と限界

各階段の接続は**既存の2×2ギャラリーパッチへの到達**であり、建物の外部入口からの完全到達やドアの開閉を保証しない。
階段と通路の案は階段ごとに独立。床開口・支持材・他階段との衝突・実Minecraft Educationのプレイヤー当たり判定の独立認証はまだない。
元の設計は変更せず、世界への実際の施工・コマンド送出は0。9 BLOCKED、NOT_PREPARED、BuildPlan.operations=[]を維持。

## 検証方法
GitHub Actionsで凍結ソース、単体テスト、全102階段の実ソース結果、安全ゲートを自動検査する。成果物はB140_15Building_TwoWide_Gallery_Bridge_Plan.jsonと日本語サマリー。
ユーザーによるZIP展開・CMD・Minecraft手動試験は今回不要。

## 次工程
独立の階段ごとの廊下提案を建物全体で共同使用できるネットワークへ統合し、上階開口、支持構造、別階段との干渉を解消する。実機でしか判断できない部分はまとめて重要な段階で試す。
