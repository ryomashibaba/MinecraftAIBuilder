# B198Z-R42 — 独創性を固定せず、実ボクセル同一性で反復表現の出力費を減らす

## 開発目的

R25の実Qwen原本は36要素を出せたものの、CUT材質違反と中実化・入口不成立・空間経路の不成立でHOLD。さらに過去R6で出力上限3072トークンに達し未完成JSONとなった。R30/R41の汎用空間優先指示を勝手に有効化せず、**AIが意図した建築形状の複雑さを減らさずにB143の記述冗長性を減らすための実測基盤**を追加する。

## R41修正

R41 Ubuntu CIで7件中6件がPASSし、指示文のケースセンシティブな`CUT` vs `cut`文字列検査のみ失敗した。テストの比較語を実際のガイド文に一致させた。B143の厳格なCUT仕様や実装は弱めない。

## R42実装

- `source/ai/b198zr42-lossless-drafting-budget.mjs`: `inspectR42AuthoringBudget(raw)` は既存の**不変の**四キー原本を解析する。必須形式検査後に正規B143コンパイルを行う。
- 出力全体の生UTF-8バイト数、正規化JSONの全体/design/spatialPlanバイト数、要素別のバイト量と形状数を計測する。
- 隣接する3個以上の同一形状・寸法・材質・modeで、等差平行移動した「連続要素群」を抽出する。用途・建築ジャンル・座標・素材・形状を決め打ちしない。
- B143の`repeat:{count,offset}`への圧縮案を**メモリ内でのみ**作り、実B143で再コンパイルする。元と候補で最終`primitives`の座標/材質/レイヤーを一つずつ照合し、完全一致かつ正規化バイト削減がある案のみ提示する。
- 元の`geometrySha256`は`design`もハッシュ入力に含むため、提案前後の比較では使えない。コンパイル結果の**primitives完全一致**を採用する。
- 中間にCUTなど他要素が入る並びはまとめない。元のADD/CUT順序を変えたり、未知の結合・ソース補正を行ったりしない。
- 正規化UTF-8バイト削減は**実モデルのトークン削減率ではない**。実Qwenを一回も使用していないので、実出力成功率や建築美観の改善を主張しない。
- 元sourceは原本であり、提案は新しい出力のための**任意の著述ヒント**。勝手に置換せず、形状の作者と実モデル成功をすり替えない。
