## 実装した動作

`executeIntegratedSemanticBridge()` は作者SHA・操作列SHAを固定したpayloadをPRIVATEホストへ渡し、作者echoを展開・コンパイルの前後で照合する。凍結B143の `verifyCompiled()` がソースSHA・幾何SHA・全最終セルを再コンパイル照合する。HOLD時にPRIVATE例外やパスを共有結果へ出さない。`privateProduct` を含む返却全体はPRIVATEであり、公開レポートではない。

`createIntegratedSpatialHost()` は `CONCEPT / SPACE / ROOF / ENTRY / SHELTER / FEATURE` を既存一体エンジンの実入力へ展開する。用途名・ジャンル名による建物選択はない。モデル側の親接続とdoor/open、屋根軸と主従、入口方向、半屋外の接続・寸法クラス、設備種別を保持し、HOSTが床・壁・屋根領域・接合・開口・柱梁・設備の実座標を処理する。既存エンジンとB143は不変更、別の建築コンパイラを追加していない。

現在の対応範囲は2〜6室、各室の機械的既定寸法12×10、shed断面、北／南入口、明示されたflatの入口半屋外空間、6種の設備。屋根主従の軒高はHOST既定7/6/5。親接続木を保って未使用の辺へ配置し、部屋間の扉は実間仕切りと開口へ変換する。入口・半屋外用の辺は確保する。未対応のgable等、東西入口、非flat半屋外、入口半屋外なし、容量不足・干渉はHOLDし、別指定へ置換しない。機械的既定寸法は建築品質を保証しない。

生成の基礎SOURCEはHOSTが明示した支持床＋交換用マーカーだけ。歴史的Qwenの原本を基礎SOURCEに偽装せず、元の床と設備を変更することもない。全新規幾何はHOST派生として記録する。
