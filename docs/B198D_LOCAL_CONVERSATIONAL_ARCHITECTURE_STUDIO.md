# B198D — Conversational AI Architecture Studio (Local Source-Only)

## Final goal and scope

MinecraftAIBuilder aims to turn the user's own free-form architectural requests into high-quality verified designs and eventually into real Minecraft Education builds **only with separate world-scoped approval**. The B198 series is quality-first:

- B198A: genuine optional LLM adapter + category-neutral B143 geometry compiler, strict source validation and safe revisions.
- B198B: 12 independent Japanese architectural intentions and 4 follow-up edits, true voxel/surface checks, separate human scoring (live inference not yet benchmarked).
- B198C: exact source-supported 2wide horizontal connected areas and enclosed-air topology, guarded real source improvement with no unsafe deletion.
- **B198D: a usable actual local interactive visual review workflow with versioned approved source, proposals, explicit accept/reject, undo/redo and same-view 3D comparison.**

Do not conflate a capable editing UI with a proven good AI architect: we have NOT executed live, paid model reasoning on all 12 B198B benchmark requests, nor human-reviewed architectural beauty. User-provided source intent and real Minecraft physics remain open quality gates.

## How to run, minimal user operations

Node.js 22+ and the repository source checkout are required. For existing source JSON generated by B198A/B198B/B198C, launch a **local source-only design studio**:

    node scripts/b198d-studio.mjs --project ./my-architecture-project --design ./source-design.json

This starts the UI on the loopback interface and prints a URL like http://127.0.0.1:<port> in the terminal. **No private network or public deployment**. With no real LLM selected, the approved 3D view/history are usable, but the model-proposal button is intentionally disabled.

On a later run, the project history is loaded from the same folder and the --design flag is not necessary:

    node scripts/b198d-studio.mjs --project ./my-architecture-project

To enable actual AI source design revisions, independently configure your provider key in the **trusted local process environment**, and pass an explicitly supported model ID:

    node scripts/b198d-studio.mjs --project ./my-architecture-project --model YOUR_ACCESSIBLE_MODEL_ID

The live provider is the existing B198A Responses adapter with explicit environment OPENAI_API_KEY. **This API is separately billed and was not used in B198D CI.** Do not paste credentials into the browser, GitHub, this chat or any source JSON. Selecting a model does not automatically create proposals: each natural-language edit is manually submitted.

## Actual browser experience

One versioned local studio displays:

1. The full **APPROVED** source design as a real rotating B143 compiled voxel exterior, with material toggles, floor cutaway and camera tools.
2. A Japanese natural-language revision textbox plus a checklist of named original parts to preserve.
3. **Propose** invokes the authorized LLM adapter. Its candidate is checked by B198A and the B198D independent compiled-source voxel-protection and original floor/headroom tests. It becomes a **DRAFT** for review only.
4. When a DRAFT exists, the viewer offers both source-accurate rotating **APPROVED** and **DRAFT** scenes (different viewer-only IDs), plus **two camera-matched side-by-side source-3D snapshots**. Adjust the interactive camera and choose "現在の視点で比較画像を更新" to refresh the paired pictures.
5. Real source diff lists added/modified/removed original element IDs, actual occupied source cell delta, and blocked original 2wide clear floor square count.
6. **Approve** is an explicit action tied to exactly one draft ID and the current approved source SHA256; anything stale is rejected. The only effect is to create one **new local SOURCE JSON snapshot**, NOT to place blocks in Minecraft.
7. **Reject** destroys the unapproved draft; the committed architecture is unchanged.
8. **Undo** travels to its previous approved original design. **Redo** returns to the previously approved version. After a new approval on an undone branch, redo is cleared, but the complete old source history remains directly inspectable, not overwritten or deleted.

### Durable state and source safety

The application saves to the chosen local project's studio-state.json, with up to 40 approved original source designs and up to 150 audit events. Each source design is immutable and recompiled/checked against its original SHA256 on load; corruption aborts loading. Updates are written to a temporary file then renamed, so previous user source paths are never overwritten. Past source versions remain recoverable even after branching.

During a pending proposal, all conflicting approve/undo/reject actions are blocked. A draft's base version is checked again after the asynchronous model call (stale generation aborts). Existing draft must be accepted or rejected before another is requested.

B198A automatically rejects malformed DSL, changed protected original element IDs, unapproved element removals, excessive broad changes and stale base SHA. B198D adds:
- Independent B198B exact compiled protected voxel/material preservation, including an added CUT silently damaging a protected element.
- Rejection if even **one originally clear 2x2 two-headroom source-standing floor square** becomes blocked or loses its four supporting cells.
- Independent before/after exact source geometry critic facts; these do not certify true walking or natural-language meaning.

### Security boundaries

- Local Node HTTP server binds **127.0.0.1 only** on an ephemeral port by default.
- Host, Origin and high-entropy CSRF header enforced on every mutation endpoint. Cross-origin and remote requests cannot use browser mutation calls; responses have no permissive CORS. Strict small JSON body limit. No filesystem path is taken from browser requests.
- Model API credential remains in the server environment; no API keys stored in project state or exposed to client HTML.
- The app exposes only source design get, propose, approve, reject, undo, redo. **No** WorldEdit, Minecraft socket, /fill, real player control, remote plugin installation, Pages publication or world build operations.
- A successful "Approve" means **local source revision accepted for review**, not explicit authorization to construct anything.
- Always readiness NOT_PREPARED, nine construction gates BLOCKED, worldCoordinates null, worldContacts=worldWrites=0, BuildPlan.operations empty.

### Evidence and what is unverified

Dedicated GitHub Actions B198D includes all **37** B198A–B198D syntax, strict source, revision guard, storage and REST security tests and actual desktop/mobile Chromium UI trials. It exercises proposal escrow, reject, approve, actual source history undo/redo, source images and side-by-side comparison. Test proposals are deliberately mock human-authored fixture designs, **not a live LLM**. Offline source-3D archive is provided as *test-only source*, without working API when opened from file://.

Human-like semantic understanding and architectural beauty, functional multi-elevation interior circulation, structural load, and actual Education world placement remain unverified. These features require later genuine model evaluation and authorized Minecraft world tests before release claims.
