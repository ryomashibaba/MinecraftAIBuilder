## なぜR13が必要か
B198Z-R6の実Qwen 1回は、`3072/3072`出力トークンで打ち切られ、JSONの最終閉じ括弧まで完成しなかった。R9～R11では、直線階段の省略・反復建築要素・簡潔な4-key出力指示を実装し、R12ではWindows軽量配布と偽モデル無しの一回操作QAが実現した。

しかし機械的にソースを生成・コンパイルできるだけでは、「**建築が実用的で美しく、凍結した日本語要求に忠実か**」を判断できない。既存 B198Wには3Dビューアーと人間による4項目ルーブリック、R3には最終概念ボクセル上の床・動線検査、R5には原本比較がある。R13では**この既存資産を重複実装せず、原本から品質判断する一枚の総合台帳**へまとめた。

## R13の仕組み
`source/ai/b198zr13-quality-decision.mjs`:
1. 凍結したB198B c01の原文・SHAを基準として、モデル原文 `raw` のSHA-256を保存。これを修正・途中補完・削除しない。
2. 同じ回答から保存した `R6_R5_UNVERIFIED_CAPTURE_RECEIPT.json` と `R6_SINGLE_CAPTURE_RESULT.json` があるなら、原文SHA・凍結プロンプトSHA・モデルID自己申告・R11原本ハッシュを照合する。**ユーザー提供の「本物」申告が合致しても本人性の独立認証は成立しない**。
3. 解析できない途中切れJSONは `HOLD_ORIGINAL_JSON_TRUNCATED_OR_INVALID` とする。実際の生原文から無理に部分3D形状を捏造しない。
4. 解析できる4-keyでも `design` が不正ならB143検査HOLD。形状はB143で完全に有効でも`spatialPlan`が欠落・不正・到達不可なら機能計画HOLD。**形状単独でコンパイル可能でも、4-keyとして合格しない**。
5. 厳格B143＋R3を通った設計には、既存 B198Wで占有セル数、寸法、立てる床の高さ、囲まれた空洞、上部ガラスの占有、凍結sourceGoals、形状の高危険検出を計算。これらは**幾何学的な証拠であり、図書館らしさ・曲面の美しさ・実プレイヤー歩行の認証ではない**。
6. 凍結日本語の4項目（公共図書館らしさ、巨大貫通吹抜け、最上階の展望ラウンジ、曲面と階層の統一感）を、初期値「人間による3Dと意味の評価待ち・採点なし」として出力。元のB198W手動評価ボードを改修せず、その機能を使う。
7. `NOT_PREPARED`、9 `BLOCKED`、`BuildPlan.operations=[]`、施工不可を全てのステータスに維持。

## 生成・再評価のユーザー体験
- **将来の新しく承認された**R6単発出力で原本を得た場合、R13の2つの結果ファイルが自動で同じZIPへ入る。
  - `R13_OFFLINE_QUALITY_DECISION.json`: 機械検査の詳細、原本SHA、異常原因と評価待ちの4項目
  - `R13_OFFLINE_QUALITY_OVERVIEW.html`: 初心者向け日本語の読みやすいHTML。既存 `index.html` 3Dビューアーと `B198W_REVIEW_BOARD.html` 手動評価票がある場合は、同じフォルダー内のローカル相対リンクを表示。外部通信なし。
- **保存済みの過去のR6証拠**も、モデルに再度接続せず監査できる。コマンド例：
```powershell
node scripts/b198zr13-review-saved-capture.mjs --evidence "C:\path\to\existing-R6-folder" --out "C:\path\to\new-R13-review"
```
  `--out` は存在しない新しいフォルダーで、元のR6フォルダーと別階層。原本が入ったフォルダーへの書込みや上書きは禁止。
- **前回のR12 MINI ZIPにはR13機能は含まれない**。その配布の固定コミットを自動変更・置換しない。
