# MinecraftAIBuilder B198Z-R78 — 建築構想を実際の空間プログラムへ落とす

基準：2026-10-22 JST。既存Draft PR #128上でR77から継続。R77 Windows/Ubuntu CIが成功していることを確認済み。main、Freeze、R48/R54原本、Minecraftワールド、Qwenの実行承認は変更しない。

## 今回の実効目標
R77の自由で大胆な建築コンセプトに対し、内側が単なる塊で終わらないための空間・用途・断面・経路の**設計上の関係**を定義する。数値を満たすだけの形状にするのではなく、海沿いの未来型公共図書館として入口、本棚、閲覧空間、大空洞、ラウンジを同じ建築に統合する。ただしR78は実際の3D形状・B143設計原本ではない。

## 8つの計画領域
1. SEASIDE_APPROACH：海辺からの公共の到着と発見できる入口。
2. ENTRY_FORUM：入口・案内・待合・左右に分岐する公共ホール。
3. CENTRAL_SKY_ATRIUM：低層から屋根高まで続く巨大な負の空間。決して歩行路ノードにはしない。
4. LEFT_BOOK_WING：左の曲面外殻の厚みにある書架・段丘・読書室。
5. RIGHT_BOOK_WING：右翼にある、左右で異なる断面リズムを持つ書架と閲覧室。
6. SUPPORTED_PUBLIC_ASCENT：階段・ランプ・外周動線など設計自由な上下移動の必要条件。
7. GLASS_STARGAZING_LOUNGE：最も高い居住可能領域にある透明な観察空間。
8. FOLDED_STRUCTURAL_ENVELOPE：外観の曲面・屋根・支持と内部の読書段丘を同じ形態にする。

## 動線と造形を混同しない
必要な動線関係は、海辺→公共ホール、公共ホール→左右書架、左右書架→昇降路、昇降路→上層ラウンジ。上記6本は**設計意図のグラフ**であり、実階段の存在やMinecraftでの歩行を保証しない。中央アトリウム・装飾外殻は歩行リンクと別の6本の空間関係として管理する。海辺の地面高、入口と階段の幅・形・支持床、各部屋のローカル座標は生成・検証されていない。

## 下から上への断面の組み立て方
- 下層：海辺から入口フォーラム、左右書架へ。中央の大空洞の起点を切り抜く。
- 中層：両翼の書架段丘と曲面外殻の厚み、中央の巨大空気を同時に成立させる。
- 上層：中央吹抜けを維持したまま側翼の公共昇降路・踊り場を成立させる。
- 最上層：透明ガラスラウンジと主要屋根・翼の支えを同じ形に統合する。

## 見た目の確認
正面・斜視・側面・俯瞰・内部アトリウム・実際の読書床という6視点で、巨大な規模と使える内部を評価する。すべての視点で審査済みとは判断していない。建築カテゴリーをリングや塔などで一律に縛らない。

## エビデンスと出力
`scripts/b198zr78-spatial-program-design-spec.mjs` でR62→R76→R77を原本から再計算し、各結果と凍結c01原文・4品質基準を照合。`auditR78SpatialProgram`は領域集合、計画上の必須接続、空洞と歩行の誤同一視、断面順序の欠落を検出するが、数値の合格を品質・安全の合格として使わない。R60 ZIPの一回レビューから`R78_ARCHITECTURAL_SPATIAL_PROGRAM.json`と`R78_LIBRARY_SECTIONS_AND_ROUTE_SPEC.html`を作成。B143不合格原本もHOLDのまま、未実行の将来計画のみ書く。改ざんや旧JSON再利用は拒否。

## 安全
新しいモデル推論やMinecraftへの接続は0回。`NOT_PREPARED`、`constructionApproved=false`、`executionAllowed=false`、施工9ゲート全て`BLOCKED`、`BuildPlan.operations=[]`、ワールド読書き0。将来Qwenへ渡す場合は新規の一度きりの明示承認が必要。設計コンセプトは提案であって固定ではなく、より良い創造的代替案を排除しない。
