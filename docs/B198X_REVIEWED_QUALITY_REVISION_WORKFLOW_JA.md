# B198X — 建築品質の評価を「次の安全な改修計画」へ接続する

## なぜこの工程が必要か

B198Wで元の凍結済み日本語指示とB143ソース実測・3Dプレビューから人間が4項目を採点できるようになりました。しかしその評価は次の設計作業には自動で引き継がれず、人間が元ソース、低評価項目、保護したい部材を何度も読み直す必要がありました。

B198Xでは**生成モデルの新規実行なしに**、保存済み設計と実際に人間が入力した4項目の根拠を照合し、優先順位・元ソースSHA・保持部材を備えた**改修ブリーフ**を作成します。この工程は**新しい建築を生成しません**。改修用のローカルLLM呼び出しを将来の人間の明示判断まで抑制します。

## 品質を落とさないための実装方針

1. 既存のB143コンパイラでモデル由来の設計をもう一度コンパイルし、元の設計SHAと幾何SHAを再照合します。B198Wの診断結果（ボクセル分布、床、空洞、素材など）は再計算し、手作業で改ざんされた評価資料による誤誘導を拒否します。
2. B198Bで固定した図書館課題の**4つの人間評価基準を変えずに**使います。各項目0～4点・15文字以上の実際の観察を要求。対象ソースと評価JSONのSHAが一致しなければHOLD。人間の評点はあくまで本人の自己申告であり、AIが美しさを認証したことにはなりません。
3. 評点0～2の項目を低い順に最大2つ（指定可能1～4件）抽出します。B198Cが検出したHIGH/MEDIUMの構造的な兆候は別欄に置き、空洞体積やガラスの位置だけで吹き抜け・展望ラウンジを完成と判定することを禁止します。高評価で数値リスクもなければ**無理に改修課題を捏造しません**。
4. B198Wレビュー画面に元のAIが出力した**ADD部材のID、形状、素材**を示し、次回必ず残したい部材をチェックできます。いずれもデフォルト未選択。選択したIDは点数・観察根拠と**同じダウンロードJSON**に保存し、別途PowerShellで選び直す作業を減らします。形式がおかしい・元の設計に存在しない・削除操作のIDであればHOLD。
5. `createB198XRevisionBrief`では、必要な低評価項目・元の日本語指示・保護する部材をJSON/Markdownに整理します。保護部材が未指定なら`DRAFT_NEEDS_EXPLICIT_PROTECTED_PARTS`に留めます。選択済みでも`REVIEWED_REVISION_BRIEF_READY_FOR_SEPARATE_AUTHORIZATION`という**次に検討するための状態**であり、実行許可ではありません。
6. 人間が書いたコメントは不信任の「観察データ」としてのみ保存します。プログラムはその文章を実行せず、モデルに自動送信せず、モデルを起動せず、部材・座標・マテリアルを直接変更しません。元のB143ソースと独立評価・人間評点をまとめたZIPを作り、次チャットでも文脈を失いにくくします。

## 使い方（初回だけ新バージョンを導入）

この操作では**Qwenは実行しません**。以前のv1/v2作業キットは触らず、新しいv3を別フォルダに作ります。

```powershell
$p = Join-Path $env:TEMP 'B198X_INSTALL_OFFLINE.ps1'
Invoke-WebRequest 'https://raw.githubusercontent.com/ryomashibaba/MinecraftAIBuilder/feature/b198x-reviewed-quality-revision-brief/tools/B198V_INSTALL_OFFLINE.ps1' -OutFile $p
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p -Model 'qwen3.8:27b'
```

`Documents/MinecraftAIBuilder-B198V/offline-workbench-v3`に以下の3つのCMDが作られます。どれも実行前にローカルのソース保存状態をSHAで検証します。

- `REPLAY_LATEST_OFFLINE.cmd`：元の設計データから3DとB198W品質評価ページを再生成。追加LLMは0回。
- `RUN_ONE_REAL_MODEL_ONCE.cmd`：新しい自由設計が本当に必要な場合だけユーザーが明示実行する、実際のQwenを使うボタン。このCMDは**数分間のモデル推論**を伴う可能性があります。
- **`PREPARE_QUALITY_REVISION.cmd`：LLMを一切呼ばない**。B198Wの3Dレビュー画面で全4項目を採点し、保護したい既存部材をチェックして保存した`B198W_HUMAN_REVIEW_c01.json`をこのCMDにドラッグ＆ドロップ。元のB143ソースSHAに一致する保存済み出力を自動検索し、要改善項目と保持対象の改修計画ZIPを作ります。ダブルクリックで起動し、評価JSONのフルパスを貼り付けても同じです。

出力は`Documents/MinecraftAIBuilder-B198M/quality-revisions`内の新規フォルダと、表示される`B198X_UPLOAD_THIS_QUALITY_PLAN_....zip`。元の設計JSON、独立したB198W診断、人間の4項目評価、改修計画JSON、日本語Markdownおよび要約を同梱し、古いソース・評価・ワールドは上書きしません。

**注意：初回の本物のQwen製でB143コンパイル成功した建築がまだない場合は、B198Wレビュー画面や有効なソースもありません。** その状態では改修計画CMDが正しくHOLDを返します。以前のB198Tの失敗ZIPは元のAI出力を含まないため、そこから成功した3Dを復元できるわけではありません。

## 実行ゲートと品質方針

- モデルが自由な形状設計を担当。プログラムはジャンル別固定テンプレートの家を生成しない。
- 保持対象は人間が選択。後のモデル修正では、既存B198Cの本物の独立B143コンパイル・保護部材と元の開放床の保全検査が必要。この段階では**モデル修正機能への自動連携は未実装**。
- モデル提案を採用するには、再コンパイルと品質・意味・見た目の再評価が必須。Minecraftでの本当の歩行や構造安全性・ワールド施工は別。
- 推論0回・ネットワーク0件（キットの導入時のGitHubダウンロードは除く）・ワールドへの接続0件・書込0件。`NOT_PREPARED`と全9ゲート`BLOCKED`。旧PR/mainは変更しない。

## 方針・計画・効率の評価

| 評価軸 | 今回の効果 |
|---|---|
| 方針 | 自由なAI造形を維持し、人間の実見を最終品質評価として独立。構造と美観の数値を混同しない。 |
| 計画 | B198U（生ソース保存）→B198V（オフライン操作）→B198W（実品質レビュー）→**B198X（評価に基づく次回改修準備）**と必要な依存関係だけを実装。 |
| 効率 | 評価点と保持部材が同じJSONになり、2分前後の不要なQwen呼び出しをせずに、品質課題・元ソース・改修条件を引き継げる。 |

**次の正しい実測:** ユーザーによる最初の有効なQwen建築の実機生成・視覚評価。この結果がない限り、実際の建築品質改善率や創造性を測定済みと称しない。
