# B138 — 15棟・66階床・102階段の接続検査と5-rise仮配置計画

## 工程の狙い
B135で4方向 `weirdo_direction` をMinecraft Educationで実測し、B136で3段の自動設置とジャンプなしの往復、B137で2つの階段列＋踊り場の5ブロック追加と下り移動を確認済み。B137の上りはタイミングにより定量未判定（68/68取得、変位+0.5）で、利用者は「視認上問題なし」と報告。この実機確認を工程ごとに繰り返すことはせず、**15棟の本来の階床・階段・水平動線へ接続するソース実装を優先する**。

## B138で実装したもの
- B113の凍結済み `assembleReferenceParent()` と `buildB113()` を直接使用してソース整合性を検証。ユーザー提供の実機ログを取り込んだと偽らない。
- 15棟それぞれの階床をノード、元の階段を隣接階床間のエッジとして構成する。1階相当（level0）から概念的に到達できる階床と、階段1つの削除で切断されるボトルネックを測定。
- すべての階床の水平廊下セル、元のドア数、B113の廊下補修後の接続候補数、追加廊下セル数を建物・階ごとに収録。ただし概念ネットワークは実際の歩行保証ではない。
- 元の階床間隔は**5ブロック**、B137で試験した2列の階段列は合計**6ブロック上昇**なのでそのまま使えない。この差を断定的な安全条件として固定。
- B113で既にソースに合う2列×長さ7の予約領域を持つ階段だけに、下段1列×2、通常オーク階段5列×2、上段1列×2の合計**14座標の仮配置**を生成する。上下の支持・開口・壁と実際に衝突しないという認証はしない。
- 候補が無い、元の階段の段差が不正、周辺動線が未接続なら**工事実行許可へ昇格しない**。候補を階段ID・建物・高さ別に優先順位付けし、次工程で元の3Dボクセルや廊下に対する本当の干渉検証を行う。
- 結果を `B138_15_Buildings_5_Rise_Connectivity.json` と初心者向けの `B138_SOURCE_CIRCULATION_SUMMARY_JA.md` としてGitHub Actionsから自動配布する。

## 検証
`.github/workflows/b138.yml` はWindowsでの手動操作不要。元のGitHub CIでコード・単体テスト・凍結ソースハッシュ・15/66/102の実データ・9件のBLOCKED・`BuildPlan.operations=[]` を検証する。合成fixtureの検証と15棟実ソースからの集計結果を明確に区別する。

## 重要な留保
- `SOURCE_LEVEL_GRAPH_REACHABLE_PROXY` は各階の接続関係が存在することを示す概念的なグラフであり、通路の幅、上階スラブ開口、ドア、頭上空間、階段の支持、ゲーム内当たり判定の合格を意味しない。
- B113の概念的な2列×7長予約領域は、3Dの障害・開口に対する十分な証明ではない。
- テスト済みB136/B137の成功は**既存102階段の成功と等価ではない**。
- 実機UP/DOWNのJSON生ファイルは会話にアップロードされていないため、ユーザーのCMD結果と目視報告のみを出典とする。
- 本工程でMinecraftへの接続、ワールド操作、施工用command列は生成しない。元の設計、main、9つのゲートは不変。

## 今後のB139での重点
概念的な各階への到達に加え、元のB105ボクセル、B123の幅2廊下接続、B124の上階開口との3D干渉を検査し、**実際の施工に使える5-rise階段ユニット**への足場を固める。実機操作を増やすより、既存凍結設計の具体的な改修と量産の実現性を優先する。
