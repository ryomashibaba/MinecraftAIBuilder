# B132 — Windows対話式校正記録のエンドツーエンド試験

## 目標

B131までに実際のWindows上でCMDの`--check`診断を確認した。B132では対話式ウィザードそのものをWindowsのCMDから実行し、終了・キャンセル・未入力拒否・合成画像の1件登録と次回起動時の整合性までを検証する。**本物のMinecraft Educationには接続せず、テスト用ワールドへも書き込まない。**

## Windows GitHub Actionsで検証する4経路

1. 通常CMD起動後に `Q` を選んで終了。証拠フォルダー・観察記録は未作成。
2. `R` を選んでも `READBACK` を明示しない場合、観察は一切保存しない。
3. `READBACK` の後に状態値が空欄の場合、`weirdo_direction=0`と誤認せず拒否。
4. CI専用一時ディレクトリの合成ファイル（Minecraft画像ではないことを明記）を使って `READBACK`・`YES` を入力し、一件の記録とローカル画像コピー・再起動後のチェックを行う。**公開する配布キットには合成記録を残さない。**

テストランナーは実際の`windows-latest`で、**空白を含むパス**に同じ配布物を置き、Windowsの`cmd.exe`で対話実行する。成功・失敗はGitHub Actionsのジョブとテスト数で判断する。

## 追加した重要な区別

B131の初期配布マニフェストは、受付データ`data/B130_Observation_Receipts.json`の初期ハッシュも記録している。これはユーザーが正当に1件登録すると変化するため、配布後の健全性判断を誤らせるおそれがある。

B132では、ランチャー・B129の原資料・5つのソースモジュールなど**不変の9ファイルを個別にSHA256で固定**した `B132_STATIC_SOURCE_MANIFEST.json` を追加。受付JSON・報告JSON・証拠画像は正常な使用によって変更されるものとして別管理する。既存B128/B129の厳密な記録スキーマとB130の証拠画像再ハッシュで動的データを検証し、真のソース改ざんと正当な記録更新を区別する。
