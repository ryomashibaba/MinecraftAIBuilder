# MinecraftAIBuilder — R36 独立R3レビュー契約の証跡監査

## 結論

R35のWindows/Ubuntu CIは両方PASS。R36では、R35で得られる**独立R3の形式的合格**を、契約作成経緯の検査なしに「独立した専門家の検証済み」と表現しないための仕組みを追加した。

R36は実Qwen推論を行わない。実Minecraft世界の接続・読込・変更・施工も行わない。実施するのは**合成データのオフライン検証**のみ。R25元モデル応答のHOLDは継続。

## 独立レビュー担当者の推奨手順

1. **モデルが出力した `spatialPlan` は見ない**。まずユーザーの元の日本語依頼、設計要件、B143が許す概念形状・最終幾何学を把握する。R3基準はモデルの自己申告の言い換えではなく、要求に基づくものとする。
2. 実際に検証したい入口（支持床と頭上空間）、到達すべき場所、意味のある機能領域、保護すべき空洞を独立に指定する。**モデルが宣言したゾーン範囲や数値を単に複写しない**。
3. 各入口・目的地・機能領域・空洞について、元の依頼との関係を文章で説明する。R36は項目IDと説明の**完全対応**を必須とする。
4. 候補原文のSHA256、独立R3契約のJSON SHA256、対象Gitコミット、要求文のSHA256、レビュー日時（UTC）を記録する。いずれもR36は**入力値の整合性のみ**を照合する。
5. R35を通過した独立契約に対してR36を実行する。契約が古いソースSHAを参照している、原文が改変されている、独立契約がモデル自己申告と同じ空間配置である、作成根拠が不足している場合はHOLD。
6. 最後に人間が設計の独創性・要望達成・実際の使いやすさを別に評価する。**R36 PASSは建築品質PASSではない**。

## R36の新しい厳格条件

`scripts/b198zr36-independent-review-provenance-offline.mjs` の `assessR36IndependentReview()`：

- **候補先行ゲート**：R34→R35の実B143・R3検証を通過していないものは即HOLD。
- **証跡パケット**：schema、レビューID、作成者の申告名、厳密なUTC日時、対象コミット（40桁）、要求SHA（64桁）、候補原文SHA、契約JSON SHA、独立性の自己申告、モデル計画未参照・非複写の自己申告、各領域の理由を必須にする。
- **ハッシュ整合性**：入力した候補・契約・要求・コミットと証跡パケットが一致しなければHOLD。独立契約を自動生成・修復・再pinしない。
- **モデル計画の複写検出**：候補の `spatialPlan` と独立契約の入口・頭上空間・空洞形状・目的地座標・利用領域形状を比較。完全一致ならHOLD。ID名やリスト順、パス許容ステップ数・到達可能セル数などの閾値を少し変えるだけでは回避できない。
- **説明の網羅性**：すべての独立契約項目について独立した理由文を要求する。未記載はHOLD。

## 正しい判定の読み方

| 判定 | 意味 |
|---|---|
| `HOLD_R35_NOT_ELIGIBLE` | B143または独立R3の形式条件を満たさない |
| `HOLD_REVIEW_EVIDENCE_FIELDS` | 証跡パケットまたは日時の記述が不正 |
| `HOLD_REVIEW_EVIDENCE_HASH_OR_COMMIT_MISMATCH` | 契約・原文・要求・コミットの照合不一致 |
| `HOLD_REVIEWER_INDEPENDENCE_NOT_CLAIMED` | 独立性を自己申告していない、モデルの計画を参照したと申告した |
| `HOLD_REVIEW_RATIONALE_INCOMPLETE` | 評価理由が不足、対象IDと一致しない |
| `HOLD_MODEL_PLAN_GEOMETRY_DUPLICATED` | モデルの空間計画と契約の幾何学的指定が一致。名称・閾値だけ変更してもHOLD |
| `REVIEWER_EVIDENCE_CONSISTENCY_PASS_AUTHORSHIP_UNVERIFIED` | **入力値・理由の整合性は形式的にPASS。ただし作成者と独立性は未認証** |

### 証明できないもの

PASS時は、与えられた証跡JSONオブジェクトの直列化SHA256（`reviewEvidenceJsonSha256`）を返す。これは入力内容の照合補助であり、ファイル原本の署名・公的タイムスタンプ・作成者の電子署名ではない。項目`reviewerEvidenceHashPinsMatchSuppliedValues`も単なる照合結果である。

レビュアー名、作成日時、元の要件、Gitコミット参照、非複写の申告はすべて**自己申告**であり、R36単独では第三者の身元・作成時刻・Git上の状態・非複写の事実を検証できない。SHA256一致も、もとのファイルを保全したという証明ではない。また、たまたま同じ幾何学指定を独立に選ぶ場合も複写検出に引っかかるため、HOLDは人間による再確認対象となる。**モデル自己申告と違う配置だからといって真の独立性が証明されるわけではない。**
