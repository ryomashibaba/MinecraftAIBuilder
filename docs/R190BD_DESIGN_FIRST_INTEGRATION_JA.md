## 3. なぜ既存実装を再利用するのか

既存の\`source/ai/b198g-local-model-adapter.mjs\`と\`scripts/r190-local-semantic-run.mjs\`には、入力日本語からモデルが\`design + spatialPlan\`を同じ一回答で出す経路、原文の取得、真正B143、3Dビュー、五方向投影、安全レシートがある。別のDSLや設計補修器を作ると、設計著作性を損ない、機能重複とコード負債を増やす。

BDはB143プリミティブや固定建築カテゴリを追加しない。出力要求の内容だけを設計思想先行に変え、形状自体はモデルの回答に委ねる。「デザインが良いはず」と推定しない。

## 4. 承認条件と実行形態

生成元の日本語依頼をSHA256固定した既存R190-BCの\`PREPARED_DIR\`が必要。ローカル研究の承認が**未提示の場合**、次のコマンドは事前検査しか行わない。

\`\`\`powershell
node scripts/r190bd-consented-design-first.mjs --from "C:\path\PREPARED_DIR" --model qwen3:14b --out "C:\path\NEW_RUN_DIR"
\`\`\`

**ユーザーがその研究1回を明示承認した場合に限って**\`--confirm-one-local-request\`を末尾に付けられる。無断実行しない。承認を得る前にこのフラグを自動付与しない。GitHub Actionsはこのフラグで実ネットワーク推論しない。実機のコマンド実行をユーザーへ要求すること自体も、事前相談と最小操作の方針を守る。

同意付きであっても実行前に\`R190BD_ATTEMPT.json\`を保存し、モデル通信失敗後の再試行を勝手に認めない。元回答が捕獲された場合のみ元原文・出所レシート・SOURCE断面を照合する。モデル原文がR4不正、用途領域が立脚不能、入口到達不能、プロバイダ完了が不確かなら**HOLD**。

## 5. 機械監査の解釈と美術の境界

- 元のモデルプロンプトと生応答はSHAで追跡し、ホストによる形状補修は0。
- 2幅・同一高さの支持床での到達だけを証明する。階段・昇降・実世界の道路・実ゲーム歩行・構造の強度を認定しない。
- SOURCE断面と真3Dが一致していても、用途・独創性・造形美の採用は独立した人間の判断が必要。
- 新規模擬テストのPASSは、**実モデルが建築を設計できたという証拠にはならない**。
- サイト規模やB143の表現域が独創性を阻害するなら、その具体的な証拠を先に集めてから表現方式を再検討する。
- 将来本試験では同一・未知の日本語要求を用い、旧型R190-R/Sと新型BDの条件差を記録。モデル生成後のSOURCE形状を美観のためにホストが勝手に改変しない。
