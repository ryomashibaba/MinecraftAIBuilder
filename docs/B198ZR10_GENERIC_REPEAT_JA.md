## 目的：R6実Qwenの3072トークン上限問題に根本対処する
R6の唯一の実Qwen推論は3,072 / 3,072出力トークンで終了し、4-keyの計画付き建築設計は未完了。R9で個別の段を一つの `staircase` にまとめた。R10では、外装リブ・柱・梁・窓等の*反復*を汎用B143要素としてコンパクト化する。

**固定の建物型テンプレート、用途別プリセット、一律の生成パターンは導入しない。** AI自身が発想した原型部材と配置をそのまま表現する言語機能のみ追加する。

## 構文
B143の `elements[]` にある既存の合法な `add`/ `cut` 要素へ任意フィールド `repeat` を追加できる。

```json
{
  "id":"facade-ribs",
  "shape":"box",
  "mode":"add",
  "material":"metal",
  "origin":[1,1,2],
  "size":[1,9,2],
  "repeat":{"count":20,"offset":[3,0,0]}
}
```

- `count` は2〜32の整数
- `offset` は各軸 -128〜128 の整数3つ `[dx,dy,dz]`、`[0,0,0]`は禁止
- 初回i=0は元の形状をそのまま描画し、i=1…count-1 は座標要素 `origin`, `center`, `start`, `end` を各軸 `i*offset` だけ平行移動する。**回転、スケール、形状改変、外部スクリプトの実行はしない**
- B143の `box`, `ellipsoid`, `cylinder`, `torus`, `beam`、R9の `staircase` をサポート。addとcutの元の性質はそのまま維持する。
- 旧 `elements[]` に repeat が無ければ、旧コンパイルの結果・形状バイト表現・設計操作リストを同一に保つ。
- `repeat` はネスト不可、未知フィールド禁止、コピーの最後の一部でも `bounds` の外に出る場合は**施工せずエラー**。負方向への配置は許すが、モデル内の実座標が負になる配置は禁止。

## データ安全制約
`MAX_WORK=1,750,000` を1配置ごとに積算する。重複箇所や `cut` によって見た目のボクセルが少なくても、すべての繰り返し実行量を計上する。最終 `MAX_CELLS=160,000` も引き続き厳格制限。実世界のMinecraftコマンドには変換しない。

モデル出力の原本SHAは **repeatを含む設計の元のJSON** を記録し、コンパイル後の実ボクセルSHAを別に保持。コンパイラーで繰り返しを展開したことを、AIが最初から20個の部材を個別に書いたと主張しない。
