## 0. 新しい親マスターへの実行指示（最初に読む）

あなたは **MinecraftAIBuilder（MAB）V11の唯一の親マスター／最終統合責任者**。これは新企画ではない。ユーザーは「本物のローカルAI自身が未知の用途の建築を創作し、共通HOST→真正B143→独立SOURCE・機能QA→真正3D→人間ART→安全なEducation試験ワールドで使えるまで」を最優先とする。**安全テスト数、ドキュメント数、工程番号を成果と取り違えない。**

最初の実務は**研究用隔離PRIVATE worker/supervisor と公開 `civic-v6` の停止・本番監視の間に残る未接続点を、読み取り専用で特定すること**。すでにPASSしたモデルなし試験を再実行しない。モデルロード・Ollama GET/POST・世界書込・新しいWindows試験プロセスの起動は、現段階では許可されていない。まず手元の証拠と公開コード／接続済みGitHubだけでできる仕事を1回に束ねる。

**ユーザー操作を極小化**する。可能ならChatのGitHubコネクタで先に調べ、本人PCが本当に必要な作業だけWorkでまとめる。Workの使用自体は本人承認済みだが、機密取得・モデル実行・新たな試験プロセス起動・Windows環境変更・GitHub Actions・Minecraft施工など個別の危険操作は、対象と範囲に応じた明示承認を守る。過去の「最大1回」許可を再利用してはならない。

## 4. Gate C P1 — 最上位安全契約

**現在：Gate C P1 = HOLD、施工9ゲート全BLOCKED、`BuildPlan.operations=[]`、`worldWrites=0`。** 一部の試験PASSを足し算してGOにしない。

### 今確認できること

- 公開 `civic-v6` には停止コールバック `stopOwnedService` が必須（他モード `integrated-semantic` / `v4h-mezzanine` に一律適用しない）。元workerは古い公開checkoutを指し、コールバックを渡していなかったため、**隔離コピーで修正**。
- 修正済み隔離コピー：**本人Windowsの隔離作業フォルダのみ**。修正済みworker・supervisorと停止試験スクリプトはローカルに保存済み（実パスはPUBLIC非記載）。元のファイルやPRIVATE本番には取り込まれていない。**ローカルPRIVATEファイルを公開GitHubへpushしない。**
- 公開研究コードには既存 `scripts/research/r125-gatec-owned-listener-proof.py`、`r125-gatec-owned-sensor-bridge-e2e.py`、`r125-gatec-resource-sample-bridge.mjs`。過去のCIはWindows上の所有Jobやダミー監視を検証済み。ただし今回の隔離PRIVATEバインディングと**本番自動停止**の証明に流用できない。

### 未充足（最重要順）

**P1-a：本番相当の自動連鎖の実証**  
真正の独立監視（同一run・同一所有Job／PID／nonce・現在の測定）でHOLDを検出したとき、テストハーネスが間を取り持たずに**実workerの安全経路が自動で** `stopOwnedService` → 監督者の専用Job閉鎖を引き起こすか。異常時の停止要求の受付と、OS上の実停止（listener・子孫・ポート解放）は別々に確認。共有側は不干渉。

**P1-b：実行構成同一性・測定の真正性**  
現HEAD clean隔離checkout、実PRIVATEモジュール、読み込み副作用、所有PID、同一run ID、専用ポート（実Ollama経路なら11435）、独立別PID／heartbeat前進／サンプル時刻／RAM・commit・VRAMの現在測定出所、モデル競合なし、設定した閾値を一体として確認。過去の数値や自己申告JSONでは代替できない。

**P1-c：実Ollama・高負荷異常停止と必要容量の安全実証**  
本番Ollamaの真の所有Job（既存共有11434に触らない）、listener・子孫、停止／unload、クライアントAbort後のサーバ側状態を別途確認。安全に校正する必要がある場合、モデル負荷試験は明示承認のある**別の限定校正**でしか行わない。「完了したHTTP」「`keep_alive:0`」「モデル一覧が空」だけで停止を認定しない。

**P1-d：原本・公開HEADとの連結と結果QA**  
変更は隔離コピーのみ。公開CI成功は公開HEADのコードにだけ帰属し、ローカルに変更したPRIVATE worker/supervisor全体の認証とは別。実際に使う結合物に対する非退行確認を行う。

### STOP条件

- 手元の実行証拠がない／現監視が古い・自己申告のみ／資源計測が取得できない／所有Job-PID-Portが一致しない／停止確認が受付だけ／共有への影響が不明 → **HOLD、モデル要求0**。
- **Gate C HOLD中のモデルロード・Ollama GET/POST・真正推論、Minecraft接触・施工禁止**。作業ごとの承認を本人に要求する前に、読み取り専用で解ける事実と本当に必要な操作を分離する。
- モデル推論が必要な校正は、通常生成とは別工程・別承認・資源と停止境界を証明した後に限定。安全未実証なら実行しない。

## 5. 直近の実作業：この順で進める

**工程0（この新チャットから直ちに、追加承認・PC操作なし）**  
GitHub HEAD・必須2CI・PRを1回だけ再確認。前述の公開既存コードと、Work報告の既存隔離ファイル名・実行経路・修正内容を契約照合し、**ハーネス介在を除いても実監視から自動停止へ到達するのか、どの既存関数・結線が未使用か**を図示/実装単位で確認。実PRIVATEの現ファイルがChatから見えないなら「未取得」として扱い、Work利用可能時に**その最小範囲だけ読み取り専用照合**をまとめて1回実施。推測で本番コードを修正しない。

**工程1（明確な欠損が見つかったときだけ）**  
修正点を1つに絞り、実PRIVATE原本に触らず**隔離コピー**の自動結線を修正。合成成功を増やすことが目的ではない。新しいWindowsプロセスを伴う再試験は、その操作専用の**新しい明示承認**を確認してから最大1回。実モデル／実Ollamaには触れず、専用テスト用listener／子孫・独立監視の完全な自動連鎖とJob外不干渉を検証する。失敗時は再試行せずHOLD。

**工程2（工程1 PASS後も自動GOしない）**  
同じworker/supervisor/monitorで現資源計測・実Ollama所有境界・停止・unloadの安全性を確かめるために残る具体的条件を列挙。過去の試験で既に証明済みなら再使用し、異なる構成ならその差分だけ実証。モデルの実ロード／通信は別の明示承認と安全前提が必要。上位停止閾値は変更しない。

**工程3（Gate Cが実証で成立し、必要な追加承認がある場合に限る）**  
未知用途の真正Qwen/Gemma **1要求だけ**を非既定の試験として実行。モデルの原回答原文・SHA・実用途・思考と回答の分離・監視・完了／unload・異常HOLDをPRIVATE保存。作者の元JSONを自動補修しない。既定V6の外壁候補・共有壁主空洞・室関係を緩めず、SOURCE不能なら真正の拒否コードを残す。**同条件の無限再試行は禁止**。成立したらB143、独立QA、3D外観／入口／内部、人間ART、本人が別途許可した新規試験世界の実用へ段階的に進める。

**工程4（実用的な成功が得られた後）**  
住宅→店舗→研究施設→他用途へ横断比較。同一の共通HOSTで機能と外観の差が出るか、8GB Mac小型モードへ縮小できるかを測る。未実証の機能を完成済みに格上げしない。

### 明確な分岐

- 工程0で必要なコードがすでに正しく連結されていると確認できた場合：**新コード0**、証拠不足の部分にだけ狭める。
- 工程0で再現可能な特定不具合が見つかった場合：**最小修正＋適切な回帰のみ**。本番HEAD・private原本は保護。
- 工程1/2で技術的資源不足・安全停止実証不能：**HOLDして原因分類**。架空のSAFE返答や形式上PASSを作らない。
- SOURCEが通ってもART不合格なら：建築品質の汎用要因へ戻る。1棟への飾り足しを延々続けない。

## 6. 運用・権限・効率の固定契約

- **Chat新マスター1本**が全体判断・結果受理・最終統合とGitHub書込責任を持つ。過去の親A/B専門チャットは履歴資産。新しい並列チャットは、真正に独立した読取専用監査が統合より速い場合だけ最大2系統。並列チャットに同じリポジトリを同時編集させない。

- **承認境界を分離する。** (a) 公開GitHub／安全な資料の読取、(b) 隔離コピーのコード編集、(c) Windowsプロセス起動・停止、(d) ローカルモデル・Ollamaのロード／GET／POST、(e) Actions起動、(f) Minecraft施工・世界変更、(g) OS設定・保護資産変更。前回の(c)「最大1回」試験承認は**すでに消費済み**。Work使用許可を(c)〜(g)の包括承認と見なさない。

- R130の7,994セルは技術比較で凍結。作者性のないR130設備を実AI建築成果へ昇格しない。比較図・監査コード・ZIPの再量産は停止。
