# B70: 床・廊下領域の非実行生成と矛盾セルの隔離

## 実装目的
本番ソース5ファイルが未取得なので、物理エンジンへの接続は不可能。収集器はB67、静的受入はB68を再利用。
B65壁・ドア / B66床マスク・予約 / B69離散シェルを検証して、**追加の建築コマンドを出さない**
概念セルの床領域RLE（行方向ラン）を生成する。モデル・資料のための新収集処理は追加しない。

## 出力
`B70_FLOOR_REGION_CANDIDATES.json` には30階にまたがる4,402行方向ラン（同じ用途の連続床セル）を収録。
- 12,778 元床マスクセルのうち10,776セル（室6,462、廊下4,314）を**局所的な候補床領域**として識別。
- 2,002セル（未分類1,444、階段288、昇降機270）は施工対象にせずHOLD。
- 別途、`office/candidate-02` の6階合計18の廊下予約が元床マスクの外にある。原図も予約も変更せず、
  `sourceConflicts.outsideReferenceFloorCorridorReservations` に記録。外側への自動延長は禁止。
- 314の室→開口→廊下の両端の候補床は概念座標上存在する。25階間の階段予約セル集合は上下で一致。

## 物理施工との違い
**候補床領域は実ブロック・スラブ・施工計画ではありません。**
セル幅の実ワールド変換、材料・床厚、階段構造/頭上空間、建築エンジンへのコード接続、実扉の開閉、
物理経路の確認は未完了。YはB66の仮想階高に従うローカル表示値のみ。
`NOT_PREPARED`、9 M4ゲート BLOCKED、`executionAllowed=false`、`BuildPlan.operations=[]`、施工命令0件を継続。

## 実行
```sh
cd source
node verify-b70-package.mjs
node parallel/b70/main/run-b70.mjs
node --test parallel/b70/main/compile-b70.test.mjs
```
`--write` はB70生成レポートだけを再保存し、B69原本以下は変更しない。
本番原本5件が到着した場合、先に **既存B68の** `--source-zip` を使い、原本コードの実行・importはしない。
B70は本番ソース0件の状態に固定されているため、受入れ後は新たな契約の実API根拠を確認してから接続方針を変更する。
