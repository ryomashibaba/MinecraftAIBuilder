# B61 — 1階D012の模式廊下接続候補と物理モジュール境界

この段階で実装したのは **B60の未接続1件を解消するオフライン幾何学候補** と、ドア78件・階段5本の非施工インターフェースである。

- 既存廊下セルは変更しない。1階D012ホール `17,18` と、出入口を含む主成分をつなぐため、B57原本床上で必要な最小の新しい3セル `(23,18) (22,18) (21,18)` を求める。
- 78/78 接続は**新しい3セルを追加した仮想グラフのみ**。既存原本に対する実装・修復・歩行確認ではない。
- 新セルの周囲の壁・部屋との干渉は未調査・未承認。新セルに実ブロックを割り付けることを禁止する。
- B43従来案の廊下35セル・壁変更20セル、B42未解決60ドア、B42/B57 2セル×5階間差をそのまま保持する。
- ドア78件・階段5本は「何の証拠が不足しているか」を記述するだけで、ブロック名、素材、状態、支持、開口、ワールド座標、施工手順の変換機能を一切持たない。
- 元の `NOT_PREPARED`、M4の9ゲート `BLOCKED`、`BuildPlan.operations=[]` は絶対維持。

## 実行（ソースZIP展開後）

```
cd source
node verify-b61-package.mjs
node --test parallel/b61/main/compile-b61.test.mjs
node parallel/b61/main/run-b61.mjs
```

`run-b61.mjs` はB60/B43/B57の固定ハッシュから再生し、結果を標準出力に表示するだけ。Minecraft、Bridge、WorldEdit、WebSocket、実施工、スキャンには接続しない。

## B62の優先

実機プロジェクトから**読み取り専用の原本ZIP**を安全に受け取り、本番 `architectural-quality.js` / `architectural-library.js` とドア・階段・間仕切りの生成箇所を静的に検証する。B61の接続候補の壁干渉と部屋占有を実データで確認し、必要なら設計変更案を比較する（未承認のまま）。
