- B18の壁5,704件・室内ドア314件・階段接続25件を、**既存ソースの設計正規化境界**と照合する読み取り専用アダプターを追加。
- 凍結済みWindowsソースの**7ファイルのバイトSHA-256一致**を再確認。対象：`general-building-planner.js`, `building-grammar.js`, `architectural-quality.js`, `architectural-library.js`, `urban_japanese.json`, `safety.js`, `build-anchor.js`。
- `GeneralBuildingPlanner.create` / `fromComposition` → `createComposition` → `rotatePlanPoint` → `validateBuildPlan` という既存の API 境界を静的に照合。**エンジンのコードはimportも実行もしない。**

- 概念階段は25件とも床・天井のスラブ開口が未設計。既存プランナーは各階に床板を生成するため、これは統合前の大きな阻害条件。
- オフィス02の外形123セル／廊下18セル差分は**未解決**。静的なドア両端のはみ出しが0件でも解決を意味しない。

## なぜM3を「部分完了」と呼ぶか

実プランナーの呼び出しを接続し、室内モジュールが現実のビルドプランとして安全に出力される段階には**まだ至っていない**。実エンジンの `fill` や `BuildPlan` と同名の出力を偽装していない。今回の成果は、実エンジンが要求する入力・座標・検証境界を固定した移植可能なアダプターである。

## 次の開発（M3後半→M4）

1. **安全な隔離テスト専用のモジュール接続口**：外装プランナーの出力と室内の意図データを操作命令を作らずに整合させる。実行コードとの混在を防ぐ。
2. **階段開口と床・天井のクリアランス**：階段が通る各フロアの床マスク・スラブ切欠きを設計し、寸法・干渉・外壁との接触を検証。
3. **量子化と材料対応**：浮動小数点の仮想壁をEducationのブロック寸法へ変換するルールと材料allowlistを実装する前に検証。`MATERIAL UNKNOWN`で拒否すること。
4. **WindowsワンパスM4**：最新版のプロセス識別、API/材料ID、隔離テスト環境を1回の安全な収集手順で確認。実施工は明示承認まで禁止。

多数の独立HTMLレビュー・細分化チェックは増やさず、上の統合に直接必要なコードに集中する。

**安全フリーズ：** `NOT PREPARED`・`BLOCKED`・施工命令0件・Legacy/既存ワールド/凍結証拠不変。
