# B39 — 階段ルートと床開口の一致（完全非施工）

## 発見

B38では東側2×2候補(15,17),(16,17),(15,18),(16,18)の床被覆は正常だったが、移動後の最上段(14,19)と入口(15,18)のマンハッタン距離が2で接続しなかった。

B39でさらに判明したのは、**凍結済み上階開口が(14,17),(14,18)**、一方の移動後シャフトはx=12..14,z=18..20であるという不一致。階段の踏面を4段・上下階高差4セル・各段に2セルの名目頭上空間とし、頭上空間が床高以上になる位置は開口でなければならないという条件を追加すると、現行開口では東側踊り場への名目ルートが作れない。

## 新しい仮想案（未採用）

- 上階の開口を(14,18),(14,19)へずらす。**変化する上階床セルは2個/階（復旧1、開口追加1）**。計5階で10セルの候補変更。元のB31/B33のデータには一切書き込まない。
- 下階の廊下に辺接触する導入セルから、同じ高さで最初の踏面へ接続。その後、階高4セルに対して4個の連続した単位段を上る。
- 各段は互いに辺接触、最上段は踊り場入口に辺接触。最上段の上面は上階の名目床高と一致。上部2段の名目頭上2セルが提案開口に一致。凍結B21の概念壁ボクセルとの重複は0としてフィルタ。
- A/B別に下階廊下の移設後状態を使用（最下階は元廊下）。5階×2案の全10条件で44名目経路を生成。

## 限界・未解決条件

**44件は物理的な安全性を検証した施工候補ではない。** 平面に投影した概念壁しか照合していない。Minecraft階段ブロックの状態、幅、曲がり角、支持梁、床・壁の実接合、手すり、上階の間仕切り、扉、上下階の避難動線、素材、ワールド座標、ランタイムの同一性、ユーザーの施工承認は一切保証しない。

今回の候補探索コードは`runner/step8b-stair-route-b39.mjs`。`BuildPlan.operations=[]`を強制し、保存レポートの改ざん（再ハッシュ付き）でもベース原本との完全再生成一致を要求する。施工ゲート9項目はすべてBLOCKED。
