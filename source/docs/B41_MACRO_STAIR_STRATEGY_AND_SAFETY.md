# B41 — 全体目標に向けた階段方式の転換と非施工の接続検証

## B40までに対して何が実際に前進したか

以前の3×3階段室に押し込む候補は44名目経路、7種類の平面署名だった。今回は、全44経路で**上昇中の向き変更**があり、14経路に**同じ平面セルの再訪**があることを追加検出した。同じX/Zを通ってもYが違う可能性があるため、再訪は即座に通行不能と判定しない。3×3空間内に4ブロック一直線に連なる踏面を配置できないことは幾何上確定。

### 実用に近づく別経路（まだ未承認）

3×3の元予約セルを1セル廊下側へ広げ、4段をX=11,12,13,14、Z=18で直線配置。導入(10,18)から、上階東側の(15,18)へつなぐ**検討専用候補**を追加した。

- 5階間すべてで再生成：床開口を(14,17)から(13,18)へ変更する仮案。床占有398セル維持、矩形6→7、再構成の欠落・重複0。
- 5階間すべてで概念壁/上階のドア・EV予約/上階床との幾何重複0。**実壁・支持材・材料状態との一致ではない。**
- 各下階で廊下の(11,18)を新しい1段目へ転用する必要あり。導入点(10,18)への概念廊下経路に到達するセルは117→115へ変化し、隣接する廊下空間に影響する。
- 検査対象の部屋ドア接続13件のうち、この導入点から到達できる件数は変更前後で12件。**元から未到達の1件があり、全室通行可能とは判定しない。**
- 床開口変更を既存プランナーへ適用していない。再設計は、床支持、階段幅、半段衝突形状、手すり、通行性、ワールド原点、材料状態を改めて検証する必要がある。

## 外部の正規資料をどのように使用したか

Microsoft Learn の Bedrock voxel shapes 文書は、階段の外形例として**下半分＋後ろの段を構成する2つの箱**を示すが、当該文書の voxel shapes は主に描画のフェイスカリング用であり、Education v26.3 のキャラクターの実衝突と同一であることを証明しない。よって本実装には方位別2箱の**可視化用プロキシ**のみを置き、実際の衝突・登坂可否は一切判定しない。

また Minecraft Bedrock の補助値/ブロック状態マッピング文書には、階段の `weirdo_direction` と `upside_down_bit` の例があるが、ユーザーのEducation実環境での状態組み合わせは未検証である。値・実材料ID・施工コマンドは生成禁止。

- https://learn.microsoft.com/en-us/minecraft/creator/documents/voxelshapes?view=minecraft-bedrock-stable
- https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/auxvaluetoblockstatemap?view=minecraft-bedrock-stable

## B42以降へまとめる次の大きな実装単位

1. **大局的な平面再設計：** 3×3維持と1セル拡張の選択。直線案で転用する廊下の幅、既存12ドアの通路と残る1ドアの問題、壁・EV・部屋との全階干渉をまとめて検証する。
2. **整数格子の立体階段契約：** 4段・方向・半段のカリング代理形状と、実際のEducationブロック状態の未検証範囲を分離。対応情報が不足するなら拒否。
3. **開口と支持の同時設計：** 上階開口の移動、床板/梁/頭上空間/階段足元支持をまとめて導出する非施工のモジュール境界を作る。
4. **オフラインのエンジン接続：** 凍結原本を改変しない開発用コピーに接続し、施工コマンド抜きで実プランナーの純粋部分を検証。明示承認前のワールド操作禁止。

完了条件はテスト件数ではなく、実装できる階段方式の確定、未対応状態の解消、Windowsで一括確認できるコンパイラ・インターフェースへの到達。
