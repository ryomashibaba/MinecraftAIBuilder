# B17 方針転換: レビューの増殖から建築エンジン統合へ

## 進捗の率直な評価

B0～B16は、Windowsディスク上のソース互換性、候補生成、外形、部屋、ドア、壁境界、階段予約、概念経路のレビューを実装した。B16の408テストPASSは**その範囲のテスト成功**に限る。汎用プランナーが室内壁・個別ドア・実階段を建築できることも、Windows稼働中の最新エンジンを特定できたことも証明していない。

B10～B16は詳細検証に偏り、物理的な自動建築完成へ直接つながるエンジン統合が遅れた。このためB17から原則レビューUIの新設をやめる。

## B17で実際に追加したもの

- `compileB17IR`: B14境界とB16接続を検証したうえで、5棟30階の安定ID付きローカルIRへ変換。
- 5,704概念壁境界、314ドア接続、25階間の階段予約を追跡。既存廊下18セルと外形123セルの未解決差分を保持。
- 各ドアが同階の壁境界IDへ確実に参照できることを検証。実ブロックの施工指示には変換しない。
- ソース5ファイルのSHA-256一致を照合。GeneralBuildingPlannerの入口APIを**文字列の静的検査**で識別。実行・インポート・Bridge通信なし。
- 未解決8項目と次の5マイルストーンを機械判定可能なJSONへまとめる。
- 改ざんしたレポートの再署名で安全ゲートを開くことができないよう、B14/B16の原本から再計算して照合。

## 開発優先度：完了の定義を明確化

| 優先順位 | マイルストーン | 必要な完了条件 | 現況 |
|---|---|---|---|
| P0 / M1 | エンジンに渡す前の厳格なIR | 原本来歴、一意ID、局所座標、未確定値の区分、施工禁止、テスト | **B17オフラインで完了** |
| P0 / M2 | **室内の実装可能なモジュール** | 間仕切り、個別ドア、階段の幾何・開口とクリアランスを孤立した純関数で試算、否定ケース含む | 未着手 |
| P0 / M3 | **実プランナーとの統合** | 外形＋室内に対する同一の正規化・衝突・材料制約を通す。ソース差分から根拠検証 | 未着手 |
| P1 / M4 | Windowsワンパス統合検証 | ソース/プロセス/材料許可リスト/エンジン版/スキャンを読み取り専用で証明 | 未着手 |
| 許可待ち / M5 | 隔離エリアCanary | **明示承認後に限り**、安全範囲・ロールバックを確認して実施工 | BLOCKED |

**次回はB18=M2の純粋な内部モジュール幾何実装に集中する。** B18をB18.1, B18.2...のようなプレビュー小工程に分割せず、室内壁→ドア開口→階段（立体クリアランス）を同一実装バッチで扱う。最初の品質ゲートは「実プランナーの正規化・安全チェックと同じ期待値を満たすこと」。

## 常に未証明のこと

- 実階段の接続・歩行性、実ドアの開閉、避難安全性。
- 教育版での実材料ID・ブロック状態、壁厚、ワールド座標、World scan、実機プロセス。
- オフィス候補02の外形123セルと廊下18セルは設計レビューでのみ解消可能。元データには絶対に適用しない。
- 施工承認。`NOT PREPARED` を強制し、IRにブロックID・世界座標・施工操作を追加しない。

## 作業高速化ルール

1. 新規UIや類似した監査の細切れ追加は行わず、M2・M3で**実装上の接続点**を減らす。
2. 既存408件を毎回全実行しない。修正箇所に依存するテスト群＋B17/B18新規異常系を即時QA、全回帰は重要統合ゲートで実施する。
3. ユーザーのWindows作業は実機情報が本当に必要な段階まで要求せず、必要になった場合のみ安全な1回の一括収集とする。
4. 軽量差分ZIPと原本のハッシュを使って復元性を維持する。旧証拠の改訂・上書きは禁止。
5. **実際の建築成功・本番完成はテスト成功と混同しない**。
