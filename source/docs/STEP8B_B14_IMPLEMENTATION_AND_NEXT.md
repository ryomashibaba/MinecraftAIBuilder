# Step 8B/B14 — 概念内部モジュール入力契約（非施工）

## 根拠と保全

B13の凍結5案 / 30階と、B12・B13のSHA-256付きレポートからのみ構築。Windows実エンジンは起動・インポート・API接続しない。B13原本の全バイトはハッシュ照合し無変更を保持する。

## B14.1–B14.6

1. **型付き局所入力**: `NOMINAL_WALL_BOUNDARY` と `NOMINAL_DOOR_INTERFACE` のローカルXZ・名目Y入力レコードを追加。`worldAnchor=null`、`materialIds=[]`、厚さ・開口高さはnull。実ブロックコマンドは作らない。
2. **境界抽出**: 凍結部屋矩形から各階の境界を重複排除し、概念ドア接続と照合。合計**5,704の概念境界辺、314の名目ドア点**。これは配置可能な壁の個数ではない。
3. **干渉検査**: 部屋同士・廊下・階段/EV予約の2D占有セル重複を検出。現行5案は重複セル0。人工的な重複・不正寸法・書き換えを検出または拒否。オフィス02の廊下18セルはエンジン予測外形からはみ出したまま。
4. **安全ゲート**: 材料ID、壁厚、ドア開口寸法、階段の実現可能性、頭上空間、実ワールド原点、稼働中エンジン同一性、建築承認はすべて未証明として遮断。`NOT_PREPARED` / `BLOCKED` / `commandCount=0`。
5. **HTMLと未承認JSON**: 建物・階・B13の4改善案切替、概念平面の可視化、未承認レビューJSON出力。実操作はChromiumのHTML本文ロードで検証。ネットワーク要求0、JS例外0。Windows file://直接起動未検証。
6. **QA・引継ぎ**: 新規23テスト（異常系・改ざん/誤承認拒否を含む）と過去の回帰確認、B13原本不変、ZIP復元確認。

## モジュールごとの未証明事項

- **壁**: 概念境界を確認しただけ。ブロック厚、柱、梁、窓、屋外/屋内境界の立体衝突は未検証。
- **ドア**: 隣接する概念セル対は存在するが、壁開口/扉ブロックの材料・向き・開閉・通行幅は未検証。
- **階段/EV**: 各階の予約位置は概念的に一致するが、踏面・蹴上げ・頭上空間・昇降の実装は未確認。
- **材料とワールド**: Educationの実ブロックID/状態、ワールド座標、プレイヤーや既存建物との干渉は未確認。

**概念レベルの不一致0 ≠ 実施工OK。** いかなる施工許可も付与しない。既存建築・Legacy設定・凍結証拠は無変更。

## 次工程 B15（まとめて実施）

施工可能な機能を実装する前に、A) 壁と部屋境界を材料無しの仮想体積として比較する入力仕様、B) ドア開口/階段クリアランスの必要測定値と未証明条件の明文化、C) 本番エンジンAPIと概念契約の差分を厳密な読み取り専用診断に統合、を優先。施工禁止のまま、非施工の図示とQAのみを許可する。
